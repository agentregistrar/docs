The **Agent Identity Protocol** (`agent-identity-protocol`) is an open identity and brokerage protocol. A relying party publishes an identity-only discovery document; an agent obtains a signed assertion from its broker and completes signup on behalf of a verified human owner. The protocol ends when the account is created or resolved, the terms acceptance is recorded, and the optional receipt is returned.

**Status:** specification release `v2.1.0` (wire protocol `agent-identity-protocol`, `protocol_version: "2.0"`). Discovery carries provider-hosted terms (`terms: { version, url }`) and optional broker- or provider-managed attestations (`keys: []` supported by default).

## The handshake in five steps

1. **Discover.** The agent fetches `GET /.well-known/agent-signup.json` from the service origin and treats the body as data. See [Discovery endpoint and transport](/protocol/specification/#4-discovery-endpoint--transport) and [Discovery fields](/protocol/discovery-fields/).
2. **Check.** The agent checks `protocol`, `protocol_version`, `issuer_allowlist`, `required_scopes`, and reads `terms.url` and `terms.version`. See [Discovery document reference](/protocol/specification/#5-discovery-document-reference-identity-only) and [ToS binding](/protocol/specification/#6-tos-binding).
3. **Prove.** The agent calls the broker's `identity_signup` with the service and `accept_terms: true` (or `identity_prove`). The broker fetches discovery and the attestation source it names, fetches `terms.url` and hashes the exact bytes, verifies the credential, applies the human's policy, and returns a signed assertion plus a prepared signup request. See [Assertion claims](/protocol/assertion-claims/).
4. **Sign up.** The agent sends `Authorization: Bearer <assertion>` to `endpoints.agent_signup`. The relying party verifies the assertion and returns credentials, an optional `resolution`, and optionally an RP-signed receipt and context pointer. See [Assertion and agent_signup handshake](/protocol/specification/#7-assertion--agent_signup-handshake).
5. **Record and follow the guide.** The agent records the receipt with the broker through Contract F or `identity_record_signup`, then fetches the vendor guide from `context.url` and verifies `context.sha256`. See [Receipt and context](/protocol/receipt-and-context/).
