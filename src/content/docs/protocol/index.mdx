The **Agent Identity Protocol** (`agent-identity-protocol`) is an open identity and brokerage protocol. A relying party publishes an identity-only discovery document; an agent obtains a signed assertion from its broker and completes signup or Day-2 re-login on behalf of a verified human owner. The protocol ends when the account is created or resolved (or a fresh session is issued), the terms acceptance is recorded, and the optional receipt or `handoff` is returned.

**Status:** specification release `v2.3.0` (wire protocol `agent-identity-protocol`, `protocol_version: "2.0"`). Discovery carries provider-hosted terms (`terms: { version, url }`), required `endpoints.agent_signup`, optional Day-2 `endpoints.agent_login`, and optional broker- or provider-managed attestations (`keys: []` supported by default). Broker metadata (`/.well-known/agent-broker.json`) advertises optional `signup_receipt_endpoint` for asynchronous Contract F receipt delivery.

## The handshake in five steps

1. **Discover.** The agent or broker fetches `GET /.well-known/agent-signup.json` from the service origin and treats the body as data. See [Discovery endpoint and transport](/protocol/specification/#4-discovery-endpoint--transport) and [Discovery fields](/protocol/discovery-fields/).
2. **Check.** The broker validates `protocol`, `protocol_version`, `issuer_allowlist`, `required_scopes`, and reads `terms.url` and `terms.version`. See [Discovery document reference](/protocol/specification/#5-discovery-document-reference-identity-only) and [terms binding](/protocol/specification/#6-tos-binding).
3. **Prove.** The agent calls the broker's `identity_signup` tool with the target `service`. The broker fetches discovery and the optional attestation source it names, fetches `terms.url` and hashes the exact response bytes, verifies the provider verification credential, applies the human owner's trust policy, records the acceptance, and returns a signed assertion inside a prepared signup request. See [Assertion claims](/protocol/assertion-claims/).
4. **Sign up.** The agent sends the prepared `POST` request with `Authorization: Bearer <assertion>` to `endpoints.agent_signup`. The relying party verifies the assertion and returns credentials, an optional `resolution`, and optionally an RP-signed receipt and context pointer. See [Assertion, agent_signup, and agent_login handshakes](/protocol/specification/#7-assertion-agent_signup-and-agent_login-handshakes).
5. **Record and follow the guide.** The agent records any returned `signup_token` with the broker through `identity_record_signup` (or the provider posts it server-to-server via Contract F), then fetches the vendor guide from `context.url` and verifies `context.sha256`. See [Receipt and context](/protocol/receipt-and-context/).
