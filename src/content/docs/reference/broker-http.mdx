This page is the endpoint reference for the broker at `https://agentregistrar.dev`:
what exists, who may call it, what it returns, and which errors it returns. For
client setup, see [Install MCP](/agents/install/); for tool schemas, see [MCP
tools](/reference/mcp-tools/); for the complete error catalog, see [Error
codes](/reference/error-codes/).

All examples use synthetic values. No endpoint accepts an API key in a query
string, and no example contains a real token.

## Authentication at a glance

| Endpoint group | Caller | Authentication |
| :--- | :--- | :--- |
| `/.well-known/*` | Anyone | None (public metadata and JWKS) |
| `POST /mcp` | Agent harness | `Authorization: Bearer mca_...` OAuth 2.1 access token |
| `GET /oauth/authorize` | Human, in a browser | Human login session (anonymous requests redirect to `/login`) |
| `POST /api/oauth/authorize/decision` | Human, in the consent page | Human login session cookie or Supabase Bearer JWT, same-origin JSON |
| `POST /api/oauth/register` | MCP client | None (RFC 7591 dynamic client registration) |
| `POST /api/oauth/token` | MCP client | One-time PKCE `S256` code or rotating refresh token |
| `GET /api/broker/provider-verification` | Anyone | None (public, read-only; `origin` and `audience` only) |
| `POST /api/broker/report-abuse` | Relying party | RP attestation + signed 5-minute report JWS |
| `POST /api/broker/report-provider` | Human owner | Human login session |
| `POST /api/broker/signup-receipt` | Relying party server | Exact historical RP attestation + RP-signed `signup_token` |
| `/api/provider/v1/*` | Provider portal or automation | Provider session or scoped provider API key (`Authorization: Bearer`) |
| `POST /api/webhooks/resend` | Mail provider only | Provider webhook signature (operator surface) |

## Discovery and metadata

| Method | Path | Status | Content type | Notes |
| :--- | :--- | :--- | :--- | :--- |
| `GET` | `/.well-known/agent-broker.json` | `200` | `application/json` | Contract I broker metadata (`v2.3.0` adds optional `signup_receipt_endpoint`). |
| `GET` | `/.well-known/oauth-protected-resource` | `200` | `application/json` | RFC 9728 protected resource metadata for `/mcp`. |
| `GET` | `/.well-known/oauth-authorization-server` | `200` | `application/json` | RFC 8414 authorization server metadata. |
| `GET` | `/.well-known/jwks.json` | `200` | `application/json` | Public Ed25519 keys. `Cache-Control: public, max-age=300`. |
| `OPTIONS` | each of the above | `204` | none | CORS preflight. |

All four set `Access-Control-Allow-Origin: *`. Only the JWKS sets an explicit
cache directive; the OAuth and broker metadata documents carry no cache header.

`GET /.well-known/agent-broker.json` (Contract I, `v2.3.0`):

```json
{
  "issuer": "https://agentregistrar.dev",
  "jwks_uri": "https://agentregistrar.dev/.well-known/jwks.json",
  "attestation_status_uri": "https://agentregistrar.dev/api/broker/attestation-status",
  "abuse_endpoint": "https://agentregistrar.dev/api/broker/report-abuse",
  "signup_receipt_endpoint": "https://agentregistrar.dev/api/broker/signup-receipt",
  "protocol_versions": ["2.0"],
  "contact": "privacy@agentregistrar.dev"
}
```

| Field | Requirement | Rule |
| :--- | :--- | :--- |
| `issuer` | required | Canonical HTTPS origin equal to the document origin and attestation `iss`. |
| `jwks_uri` | required | Absolute HTTPS URL (no userinfo), same origin as `issuer`. |
| `attestation_status_uri` | required | Absolute HTTPS URL (no userinfo) for legacy signed attestation status queries. |
| `abuse_endpoint` | required | Absolute HTTPS URL (no userinfo) accepting Contract D.2 abuse reports. |
| `signup_receipt_endpoint` | optional (`v2.3.0`) | Absolute HTTPS URL (no userinfo) accepting Contract F signup receipts. Cross-origin allowed under SSRF rules; same-origin recommended. Fallback when omitted: `<issuer>/api/broker/signup-receipt`. |
| `protocol_versions` | required | Non-empty unique array containing `"2.0"`. |
| `contact` | required | Email address or absolute HTTPS URL. |

Unknown properties are forbidden (`additionalProperties: false`). See [spec section 16](/protocol/specification/#16-contract-i--broker-metadata-and-attestation-status).

`GET /.well-known/oauth-protected-resource`:

```json
{
  "resource": "https://agentregistrar.dev/mcp",
  "authorization_servers": ["https://agentregistrar.dev"],
  "bearer_methods_supported": ["header"],
  "scopes_supported": ["mcp:tools", "tos:accept", "signup:free_tier"]
}
```

`GET /.well-known/oauth-authorization-server`:

```json
{
  "issuer": "https://agentregistrar.dev",
  "authorization_endpoint": "https://agentregistrar.dev/oauth/authorize",
  "token_endpoint": "https://agentregistrar.dev/api/oauth/token",
  "registration_endpoint": "https://agentregistrar.dev/api/oauth/register",
  "jwks_uri": "https://agentregistrar.dev/.well-known/jwks.json",
  "response_types_supported": ["code"],
  "grant_types_supported": ["authorization_code", "refresh_token"],
  "token_endpoint_auth_methods_supported": ["none", "client_secret_post"],
  "code_challenge_methods_supported": ["S256"],
  "client_id_metadata_document_supported": true,
  "scopes_supported": ["mcp:tools", "tos:accept", "signup:free_tier"]
}
```

`GET /.well-known/jwks.json` (key material shortened):

```json
{
  "keys": [
    {
      "kty": "OKP",
      "crv": "Ed25519",
      "x": "<32-byte public key, base64url>",
      "kid": "broker-key-1",
      "alg": "EdDSA",
      "use": "sig"
    },
    {
      "kty": "EC",
      "crv": "P-256",
      "x": "<32-byte x coordinate, base64url>",
      "y": "<32-byte y coordinate, base64url>",
      "kid": "broker-es256-1",
      "alg": "ES256",
      "use": "sig"
    }
  ]
}
```

The `iss` in an assertion equals this issuer origin. Native Agent Identity Protocol assertions carry `alg` `EdDSA`, a `kid` matching the Ed25519 key in the issuer's current JWKS, and `typ` `agent-id+jwt`. For `auth.md` interoperability, `oauth-id-jag+jwt` assertions and `secevent+jwt` revocation tokens carry `alg` `ES256` and a `kid` matching the `P-256` key; see [Already using auth.md?](/providers/auth-md/). Verify against the JWKS, never against a key URL supplied by the assertion, and never hard-code `kid`. See [Issuer and JWKS assumptions](/protocol/specification/#10-issuer--jwks-assumptions).

## OAuth 2.1 with agent binding

The broker implements authorization code with PKCE `S256`, atomic rotating
refresh tokens, and explicit agent sub-identity binding at consent time. It
supports three client types:

- **Dynamic client registration (DCR)** clients registered via `POST /api/oauth/register` (`cli_...`).
- **Pre-seeded loopback CLI clients** for common harnesses.
- **Client ID Metadata Document (CIMD)** clients whose `client_id` is an HTTPS URL serving client metadata (`client_id_metadata_document_supported: true`).

Default OAuth scopes are `mcp:tools`, `tos:accept`, and `signup:free_tier`.
Newly created agents receive default agent scopes `tos:accept`,
`signup:free_tier`, and `inbox:read`.

### POST /api/oauth/register

RFC 7591 dynamic client registration. No authentication. Request body:

| Field | Type | Required | Default | Rule |
| :--- | :--- | :-: | :--- | :--- |
| `client_name` | string | no | `MCP Client` | Display name. |
| `redirect_uris` | array of strings | yes | - | At least one. Each must be HTTPS, or HTTP on a loopback host (`localhost`, `127.0.0.1`, `::1`). Fragments and other schemes are rejected. |
| `grant_types` | array of strings | no | `["authorization_code","refresh_token"]` | Supported grant types. |
| `response_types` | array of strings | no | `["code"]` | Supported response types. |
| `token_endpoint_auth_method` | string | no | `none` | Public clients use `none`. |

Success is `201`:

```json
{
  "client_id": "cli_01jdocsverify000000000000",
  "client_id_issued_at": 1792576800,
  "client_name": "Example MCP client",
  "redirect_uris": ["http://127.0.0.1:33418/callback"],
  "grant_types": ["authorization_code", "refresh_token"],
  "response_types": ["code"],
  "token_endpoint_auth_method": "none"
}
```

| Status | `error` | Meaning |
| :--- | :--- | :--- |
| `400` | `invalid_redirect_uri` | A redirect URI is not loopback HTTP or HTTPS, or the list is empty. |
| `400` | `invalid_client_metadata` | Invalid JSON or a body that fails the metadata schema. |
| `500` | `server_error` | The client could not be persisted. |

### GET /oauth/authorize

The browser consent page. Query parameters:

| Parameter | Required | Rule |
| :--- | :-: | :--- |
| `client_id` | yes | Registered `cli_...` id, pre-seeded client id, or HTTPS CIMD URL. |
| `redirect_uri` | yes | Must match a registered redirect URI for that client. |
| `response_type` | yes | `code`. |
| `code_challenge` | yes | Non-empty PKCE challenge. |
| `code_challenge_method` | yes | `S256`. |
| `state` | no | Returned unchanged on callback. |
| `scope` | no | Space-delimited; defaults to `mcp:tools tos:accept signup:free_tier`. |
| `resource` | no | Stored with the authorization code. |

Behavior:

- Anonymous requests receive `307` to `/login?next=<encoded authorize URL>`.
- Invalid parameters render an HTML error card and never redirect to an
  unvalidated `redirect_uri` (`invalid_client`, `invalid_redirect_uri`,
  `unsupported_response_type`, or `invalid_request`).
- Valid requests render the consent card where the human reviews the client
  name and scopes, optionally signs the Master Agent Delegation Agreement
  inline, and chooses whether to **reuse an existing active agent** (recommended
  when adding a new laptop or harness, showing each agent's name, inbox, and
  connected service count) or **create a new isolated agent**.

### POST /api/oauth/authorize/decision

Submits the human's consent decision and binds the resulting authorization code
to one active agent sub-identity. Same-origin JSON with the human session cookie
(or Supabase Bearer token). Body:

| Field | Type | Required | Meaning |
| :--- | :--- | :-: | :--- |
| `client_id` | string | yes | Client being authorized. |
| `redirect_uri` | string | yes | Must match the client registration. |
| `code_challenge` | string | yes | PKCE challenge from `/oauth/authorize`. |
| `code_challenge_method` | string | no | `S256` (default). |
| `state` | string | no | Echoed into `redirect_url`. |
| `scope` | string | no | Space-delimited scopes. |
| `resource` | string | no | Stored with the authorization code. |
| `decision` | `"approve"` or `"deny"` | yes | Human consent decision. |
| `accept_master_tos` | boolean | no | Record the current Master Agent Delegation Agreement signature inline. |
| `agent_mode` | `"create"` or `"existing"` | no | Whether to create a new agent sub-identity or bind an existing active one. Defaults to `"existing"` if `agent_id` is supplied without `"create"`, otherwise `"create"`. |
| `agent_name` | string | no | Display name when `agent_mode` is `"create"`. Defaults to `client.client_name`. |
| `agent_id` | string (`agt_...`) | conditional | Required when `agent_mode` is `"existing"`; must reference an `active` agent owned by this human. |

Agent-binding rules enforced on approval:

- If **any** agent on the human's account has `status = "suspended"` (operator
  protective suspension), approval is blocked with `403 access_denied`.
- When creating a new agent, the broker enforces `max_active_agents` (default
  `2` active agents per human). Exceeding the cap fails with `403
  agent_limit_reached`; connect to an existing active agent or revoke an unused
  agent in the [Developer Portal](/agents/portal/).
- The chosen or newly created `agent_id` is stored on the one-time `mcc_...`
  authorization code and propagated to every token issued from that grant.

Success is `200` with `{ "redirect_url": "..." }`. A denial also returns `200`
with `error=access_denied` in `redirect_url`.

| Status | `error` | Meaning |
| :--- | :--- | :--- |
| `401` | `unauthorized` | No authenticated human session. |
| `400` | `invalid_request` | Invalid JSON, schema failure, or selected `agent_id` not found / not active. |
| `400` | `invalid_client` | The client cannot be resolved. |
| `400` | `invalid_redirect_uri` | The redirect URI does not match the client. |
| `400` | `master_tos_required` | Current Master Agent Delegation Agreement is unsigned and `accept_master_tos` was not `true`. |
| `403` | `access_denied` | Human account is suspended, or an agent on the account is operator-suspended. |
| `403` | `email_verification_required` | Human email address is not verified. |
| `403` | `agent_limit_reached` | Active agent count has reached `max_active_agents` (default `2`). |
| `500` | `server_error` | Failed to record signature, create agent, or store authorization code. |

### POST /api/oauth/token

Exchanges a one-time authorization code or atomically rotates a refresh token.
Accepts `application/x-www-form-urlencoded` or `application/json`.

`grant_type=authorization_code`:

| Parameter | Required | Meaning |
| :--- | :-: | :--- |
| `grant_type` | yes | `authorization_code`. |
| `code` | yes | One-time `mcc_...` code (10-minute lifetime, atomically claimed). |
| `code_verifier` | yes | PKCE verifier matching the stored `S256` challenge. |
| `client_id` | no | When present, must match the code's client. |
| `redirect_uri` | no | When present, must match the code's redirect URI. |

`grant_type=refresh_token`:

| Parameter | Required | Meaning |
| :--- | :-: | :--- |
| `grant_type` | yes | `refresh_token`. |
| `refresh_token` | yes | Rotating `mcr_...` token; atomically revoked before issuing the replacement pair. |
| `client_id` | no | When present, must match the token's client. |

Both grants verify that the human owner is `active`, email-verified, has signed
the current Master Agent Delegation Agreement, and that the bound `agent_id` is
still `active`.

Success is `200` with `Cache-Control: no-store` and `Pragma: no-cache`:

```json
{
  "access_token": "mca_<64 hex>",
  "token_type": "Bearer",
  "expires_in": 86400,
  "refresh_token": "mcr_<64 hex>",
  "scope": "mcp:tools tos:accept signup:free_tier"
}
```

Access tokens live 24 hours (`86400` seconds). Tokens are opaque; only their
SHA-256 hashes are stored.

| Status | `error` | Meaning |
| :--- | :--- | :--- |
| `400` | `invalid_request` | Missing `code`/`code_verifier` or missing `refresh_token`. |
| `400` | `invalid_grant` | Unknown/expired/used code, PKCE mismatch, unknown/revoked refresh token, inactive/unverified/unsigned human, or inactive bound agent. |
| `400` | `unsupported_grant_type` | `grant_type` is not `authorization_code` or `refresh_token`. |
| `500` | `server_error` | Token pair could not be persisted. |

## MCP transport

### POST /mcp

Stateless Streamable HTTP MCP endpoint. Send JSON-RPC 2.0 with
`Content-Type: application/json` and `Authorization: Bearer mca_...`.

| Request | Result |
| :--- | :--- |
| Valid bearer, valid JSON-RPC | `200` with a JSON-RPC response (`initialize`, `tools/list`, `tools/call`, `resources/list`, `resources/read`). |
| Missing, invalid, expired, or revoked token | `401`, JSON-RPC code `-32001`, plus `WWW-Authenticate` header. |
| Human suspended, email unverified, or current Master Agreement unsigned | `403`, JSON-RPC code `-32003`. |
| No acceptable media type | `406`, JSON-RPC code `-32000`. |
| CORS preflight (`OPTIONS`) | `204`, no body. |

`401` response with RFC 9728 challenge header:

```http
HTTP/2 401
content-type: application/json
www-authenticate: Bearer resource_metadata="https://agentregistrar.dev/.well-known/oauth-protected-resource", scope="mcp:tools tos:accept signup:free_tier"

{"jsonrpc":"2.0","error":{"code":-32001,"message":"Unauthorized: Missing, invalid, expired, or revoked MCP Bearer token."},"id":null}
```

`POST` accepts `Accept: application/json` alone; the handler normalizes it to
`application/json, text/event-stream` and defaults a missing `Content-Type` to
`application/json`. Use `POST` for every MCP request; the transport is stateless
and has no server-initiated SSE stream to resume on `GET` and no session state
to tear down on `DELETE`.

CORS headers applied to every `/mcp` response (including errors):

| Header | Value |
| :--- | :--- |
| `Access-Control-Allow-Origin` | `*` |
| `Access-Control-Allow-Methods` | `GET, POST, DELETE, OPTIONS` |
| `Access-Control-Allow-Headers` | `Authorization, Content-Type, Accept, Mcp-Session-Id, Mcp-Protocol-Version, Last-Event-ID` |
| `Access-Control-Expose-Headers` | `WWW-Authenticate, Mcp-Session-Id, Mcp-Protocol-Version` |

## Broker APIs

### GET /api/broker/provider-verification

Public broker-managed attestation source (Contract G, `broker` mode). Callers
use the exact `attestation.uri` from discovery and never add extra parameters.
Only `origin` and `audience` are sent, so no agent or human identifier is
exposed.

```http
GET /api/broker/provider-verification?origin=https%3A%2F%2Fprovider.example&audience=example
```

| Parameter | Required | Rule |
| :--- | :-: | :--- |
| `origin` | yes | Canonical provider origin, percent-encoded. No path or wildcard. |
| `audience` | yes | Discovery `audience`. |

A current, active attestation returns `200` with `Content-Type: application/json`,
`Cache-Control: public, max-age=300`, `Access-Control-Allow-Origin: *`, and:

```json
{
  "attestation": "<compact agent-rp-attestation+jwt JWS>"
}
```

Every non-`200` response sets `Cache-Control: no-store`. The broker renews the
token on demand when 12 hours or less remain and never serves a token for a
suspended or revoked provider.

| Status | `error` = `code` | Meaning |
| :--- | :--- | :--- |
| `200` | - | Current attestation in `{ "attestation": "<JWS>" }`. |
| `400` | `invalid_request` | Missing, extra, duplicate, or non-canonical query parameters. |
| `403` | `provider_suspended` | Provider or origin is suspended. |
| `404` | `attestation_not_found` | Unknown pair, wrong publication mode, unverified origin, or no attestation. Maps to `unverified`. |
| `410` | `attestation_revoked` | Provider or latest attestation is revoked. Maps to `invalid` with reason `attestation_revoked`. |
| `429` | `rate_limited` | Per-IP rate limit exceeded; `Retry-After` is set. |
| `503` | `broker_unavailable` | Database or signing failure. |

### POST /api/broker/signup-receipt

Contract F server-to-server receipt ingestion, advertised as
`signup_receipt_endpoint` in `GET /.well-known/agent-broker.json` (`v2.3.0`).
Relying parties should discover the URL from Contract I metadata (falling back
to `<issuer>/api/broker/signup-receipt`) and deliver asynchronously from a
durable outbox. Both body fields are required:

```json
{
  "signup_token": "<compact Contract E RP-signed receipt>",
  "rp_attestation": "<exact historical attestation named by service.attestation_jti>"
}
```

The broker verifies the historical attestation (exact `jti`, never substituting
a newer attestation), checks the receipt `iat`/`signed_up_at` against that
attestation's `[iat, exp]` window, verifies the receipt with `service.key_id`,
and records `proof_source: "rp_callback"`.

Success is `201` (created) or `200` (deduplicated or upgraded from Tier 2):

```json
{
  "ok": true,
  "signup_id": "7f651102-docs-4fa6-b700-000000000000",
  "signup_token_jti": "srp_01jdocsverify00000000000",
  "assertion_jti": "jti_01jdocsverify0000000000000",
  "agent_id": "agt_01jdocsverify0000000000000",
  "service_audience": "example-provider",
  "provider_account_id": "840d6148-docs-4680-8f33-000000000000",
  "human_email_shared": "human@example.com",
  "context_url": "https://example.com/docs/SKILL.md",
  "context_sha256": "sha256:1111111111111111111111111111111111111111111111111111111111111111",
  "proof_source": "rp_callback",
  "deduplicated": false
}
```

Retry on network errors, `429` (honoring `Retry-After`), `503
rp_broker_unavailable`, and other `5xx` responses; treat `200`, `201`, `400`,
`401`, and `409` as terminal. See [spec section
11](/protocol/specification/#11-contract-e-identity-facts--the-context-pointer),
[Receipts and context guide](/providers/guides/issue-signup-receipt/), and
[Provider API and Contract F/D.2
errors](/reference/error-codes/#provider-api-and-contract-fd2-errors).

### POST /api/broker/report-abuse

Authenticated relying-party abuse reporting (Contract D.2). Opens an abuse case
and never deletes provider accounts. Request body (64 KiB limit):

```json
{
  "rp_attestation": "<current compact provider attestation JWS>",
  "report": "<compact agent-rp-abuse+jwt JWS (5-minute window)>"
}
```

The broker checks `rp_attestation` against its RP-broker trust list before any
JWKS fetch, verifies `report` with `kid`, and checks for a linked RP-signed
signup (`rp_callback` or `rp_signed`) with a verified signup-time attestation.
Only a `verified` report may apply a protective suspension pending operator
review; an unverified report opens a case without suspending.

A new accepted report returns `202` (duplicate returns `200` with the same
`case_id`):

```json
{
  "case_id": "0d5f6a7c-...",
  "report_jti": "abr_01j...",
  "verification_status": "verified",
  "deduplicated": false,
  "agent_suspended": true,
  "human_notified": true
}
```

See [Abuse reporting](/providers/guides/abuse-reporting/) for the signing guide.

### POST /api/broker/report-provider

Human session only. Used by the [Developer Portal](/agents/portal/) so a human
owner can report a provider (origin, audience, optional attestation `jti`,
reason, optional evidence, and optional `distrust_broker` or `block_provider`
flags). Creates a provider case and can update the human's local trust policy;
it does not alter the provider's attestation.

### POST /api/webhooks/resend

Operator surface only. Receives inbound mail and delivery events from the mail
provider, verified with webhook signature headers (`401 invalid_webhook_signature`
otherwise). Agents, harnesses, and relying parties must not call it.

## Provider Portal API (`/api/provider/v1/*`)

The [Provider Portal](/providers/portal/) and provider automation use scoped
REST endpoints under `/api/provider/v1/*`. Every response sets
`Cache-Control: no-store` and returns JSON. Errors use
`{ error, error_description, code }` (with `WWW-Authenticate: Bearer realm="provider-api"` on `401`).

### Provider API key scopes

Bearer keys (`Authorization: Bearer <provider_api_key>`) carry one or more of
six scopes:

| Scope | Permission |
| :--- | :--- |
| `account:read` | Read provider account, status, plan, and entitlements. |
| `keys:write` | Request key challenges and register, retire, or revoke RP signing keys. |
| `attestation:read` | Read the current provider attestation. |
| `attestation:write` | Issue or renew a provider attestation. |
| `events:read` | Read paginated organization events from `GET /api/provider/v1/events`. |
| `webhooks:write` | Manage webhook endpoints, rotate secrets, send test pings, read deliveries, and replay deliveries under `/api/provider/v1/webhooks/*`. |

### Route groups

| Route group | Purpose |
| :--- | :--- |
| `/api/provider/v1/accounts`, `/api/provider/v1/account`, `/api/provider/v1/account/contact` | Create and manage provider organization accounts and security/abuse contacts. |
| `/api/provider/v1/services`, `/api/provider/v1/services/[id]`, `.../retire`, `.../discovery`, `.../checks`, `.../go-live` | Create services, inspect generated discovery snippets, run live readiness checks, go live, or retire a service. |
| `/api/provider/v1/services/[id]/origins`, `.../[originId]/challenge`, `.../verify`, `.../primary`, `.../retire` | Register origins, issue and verify DNS or `.well-known` domain challenges, promote primary origins, or retire origins. |
| `/api/provider/v1/services/[id]/dry-run`, `.../dry-run/challenge`, `.../dry-run/receipt` | Run end-to-end assertion and receipt dry-run tests from the Provider Portal. |
| `/api/provider/v1/keys`, `.../keys/challenge`, `.../keys/[kid]/retire`, `.../keys/[kid]/revoke` | Register Ed25519 signing keys with proof-of-possession (optional; required only for signed receipts or abuse reporting), retire, or revoke keys. |
| `/api/provider/v1/attestation` | Inspect or rotate the provider's verification credential (`broker` default or `provider` opt-in). |
| `/api/provider/v1/api-keys`, `.../api-keys/[id]/revoke` | Issue and revoke scoped provider API keys (`account:read`, `keys:write`, `attestation:read`, `attestation:write`, `events:read`, `webhooks:write`). |
| `/api/provider/v1/webhooks`, `/api/provider/v1/webhooks/[id]`, `.../rotate-secret`, `.../test`, `.../deliveries`, `.../deliveries/[deliveryId]/replay` | Create, update, delete, rotate secrets, ping, inspect deliveries, and replay deliveries for signed outbound webhooks. |
| `/api/provider/v1/events` | Cursor-paginated Pull Events API over the 1-year organization audit log. |
| `/api/provider/v1/members/*`, `/api/provider/v1/ownership/transfer/*` | Manage team members, invites, roles, and organization ownership transfer. |

### Provider Webhooks API (`/api/provider/v1/webhooks/*`)

All webhook endpoints require the `webhooks` plan feature (enabled on `free` and
`pro`) and enforce `max_webhook_endpoints` (`5` on `free`, `15` on `pro`).
Mutations require an active provider organization (`provider_accounts.status = "active"`).
Session callers need `owner` or `admin` for mutations and any role (`owner`,
`admin`, `member`) for reads; API key callers require `webhooks:write`.

| Method | Path | Success | Auth | Request / Response contract |
| :--- | :--- | :-: | :--- | :--- |
| `GET` | `/api/provider/v1/webhooks` | `200` | Member session or `webhooks:write` | Returns `{ endpoints }` (never returns encrypted or plaintext secrets; includes `secret_prefix` and `previous_secret_expires_at`). |
| `POST` | `/api/provider/v1/webhooks` | `201` | Owner/admin session or `webhooks:write` | Body `{ url, description?, subscribed_events }`. `url` must be a public HTTPS URL (max `2048` chars, SSRF-checked); `description` optional string or `null` (max `256` chars); `subscribed_events` non-empty array of subscribable event types. Returns `{ endpoint, signing_secret }` with plaintext `whsec_...` shown **once**. |
| `GET` | `/api/provider/v1/webhooks/[id]` | `200` | Member session or `webhooks:write` | Returns `{ endpoint }` without secrets. |
| `PATCH` | `/api/provider/v1/webhooks/[id]` | `200` | Owner/admin session or `webhooks:write` | Body requires at least one of `{ url?, description?, subscribed_events?, enabled? }`. Re-enabling an auto-disabled endpoint clears `disabled_reason` and resets failure counters. Returns `{ endpoint }`. |
| `DELETE` | `/api/provider/v1/webhooks/[id]` | `200` | Owner/admin session or `webhooks:write` | Deletes the endpoint and cancels pending deliveries. Returns `{ id, deleted: true }`. |
| `POST` | `/api/provider/v1/webhooks/[id]/rotate-secret` | `200` | Owner/admin session or `webhooks:write` | Body `{ grace_hours?: 0..168 (default 24), expire_previous_now?: boolean (default false) }`. Returns `{ endpoint, signing_secret }`, where `signing_secret` is the new plaintext `whsec_...` (shown **once**) on rotation, or `null` when `{ "expire_previous_now": true }` clears the retiring secret without rotating the active secret. |
| `POST` | `/api/provider/v1/webhooks/[id]/test` | `200` | Owner/admin session or `webhooks:write` | Dispatches a signed `webhook.test` delivery synchronously and returns `{ delivery, attempt }`. |
| `GET` | `/api/provider/v1/webhooks/[id]/deliveries` | `200` | Member session or `webhooks:write` | Query params `cursor`, `limit`, `status`. Returns `{ deliveries, next_cursor, has_more }` (retained 30 days) with status (`pending`, `in_flight`, `delivered`, `dead_letter`, `canceled`), `attempt_count`, HTTP status, latency, and sanitized response snippet (max `512` bytes). |
| `POST` | `/api/provider/v1/webhooks/[id]/deliveries/[deliveryId]/replay` | `202` | Owner/admin session or `webhooks:write` | Resets a failed, `dead_letter`, or `canceled` delivery scoped to `(id, provider_id)` back to `pending`, schedules an immediate delivery attempt, and returns `{ delivery }`. |

Outbound webhook delivery contract (see [Receive signed webhooks](/providers/webhooks/) for copy-paste verifiers):

- **Headers:** `Content-Type: application/json; charset=utf-8`, `User-Agent: AgentRegistrar-Webhooks/1.0`, `X-AgentRegistrar-Delivery-Id: whd_<ulid>`, `X-AgentRegistrar-Event: <event_type>`, `X-AgentRegistrar-Timestamp: <unix_seconds>`, `X-AgentRegistrar-Signature: v1=<hex>[,v1=<hex>]`.
- **Signature:** `HMAC-SHA256(utf8(whsec_...), utf8("${timestamp}.${raw_utf8_json_body}"))` as lowercase hex; verify within `+/- 300` seconds in constant time.
- **Envelope:** `{ id: "evt_<ulid>", type, api_version: "2026-11-23", created_at, provider_id, data }`.
- **Subscribable `type` values:** `agent.status_changed`, `abuse.case.updated`, `service.health_changed`, `signup.confirmed`, `signup.conflict`, `attestation.expiring`, `attestation.status_changed` (plus manual `webhook.test`).
- **Transport:** HTTPS-only with pre-connect public-IP DNS check, redirects disabled (`3xx` fails as `redirect_blocked`), `5,000` ms timeout, `2xx` required for delivery, 7 attempts (`immediate`, `+5m`, `+15m`, `+1h`, `+4h`, `+12h`, `+24h` -> `dead_letter`), circuit breaker auto-disables after `>= 10` consecutive failures spanning `>= 24` hours.

### Pull Events API (`GET /api/provider/v1/events`)

Cursor-paginated read endpoint over `provider_events` (requires the `events_api`
plan feature, enabled on `free` and `pro`). Accessible with a provider API key
carrying `events:read` or a provider session (`owner`, `admin`, or `member`).

| Query parameter | Type | Default | Constraint |
| :--- | :--- | :--- | :--- |
| `cursor` | string | omitted | Opaque cursor (`1..256` chars) from the prior page. |
| `limit` | integer | `25` | `1..100`. |
| `type` | string | omitted | Frozen `provider.*` event name (see [Pull events and audit log](/providers/events-and-audit/#event-catalog)). |
| `service_id` | UUID | omitted | Scope results to one service in the provider organization. |
| `since` | ISO 8601 datetime with offset | omitted | Lower time bound; clamped to the 1-year (`365`-day) retention lookback window. |
| `until` | ISO 8601 datetime with offset | omitted | Upper time bound. |

Returns `200` with `{ events, next_cursor, has_more }`. Each event row carries
`id`, `provider_id`, `event_type`, `actor_kind` (`member`, `operator`,
`system`), `actor_human_id`, `service_id`, `request_id`, `metadata`, optional
redacted scalar `changes` (max `1,024` UTF-8 bytes), and `created_at`. Raw
client IP addresses, User-Agent strings, secrets, and provider credentials are
never stored or returned.
