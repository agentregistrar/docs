This page is the canonical error catalog across every layer of Agent Registrar
and the Agent Identity Protocol. Identify the layer first, then branch on
`code` (or `error`) and `retryable`. Human-readable `message` and
`error_description` strings may change and are not for control flow.

| Layer | Where it appears | Envelope shape |
| :--- | :--- | :--- |
| Discovery validation | Conformance validator CLI | Exit code (`0`, `1`, `2`) plus `errors`, `warnings`, `conformance`, `attestation` |
| MCP transport | `POST /mcp` before any tool runs | HTTP status plus JSON-RPC `error` object (`id: null`) |
| MCP tools | Inside a tool result | HTTP `200` with `isError: true` and `{ error: { code, message, retryable, side_effects, next_step?, docs, extra? } }` |
| Provider handshake | Relying party's `POST endpoints.agent_signup` / `endpoints.agent_login` | HTTP status plus `{ error, error_description?, retryable? }` (plus Day-2 step-up/terms fields) |
| Broker APIs and OAuth | `/api/broker/*`, `/api/provider/v1/*`, `/api/oauth/*` | HTTP status plus `{ error, error_description, code? }` |

## MCP tool error envelope

Every MCP tool failure returns `isError: true` with this JSON string in
`content[0].text` (never `structuredContent`):

```json
{
  "error": {
    "code": "rp_unverified",
    "message": "The relying party is not verified and the human owner's policy requires verification.",
    "retryable": false,
    "side_effects": {
      "acceptance_recorded": false,
      "acceptance_created": false,
      "ledger_email_sent_to_agent": false,
      "ledger_email_forwarded_to_human": false,
      "rp_verification_recorded": false,
      "rp_verification_reused": false,
      "assertion_minted": false
    },
    "next_step": "Ask the human owner to change the RP policy or use a verified provider. Nothing was minted.",
    "docs": "agentregistrar://docs/error-recovery"
  }
}
```

Always read `side_effects` before retrying: it reports exactly what the failed
call wrote so you know whether retrying can duplicate a side effect.

## Discovery validation exit codes

The conformance validator is a producer audit tool, not an agent-facing error
envelope:

| Exit | Meaning | Next action |
| :--- | :--- | :--- |
| `0` | Document fetched, parsed, and conformant; no required verification failed. Warnings do not fail exit `0`. | Publish. `attestation.status` may still be `unverified`, `expired`, or `invalid` unless `--require-attestation` is set. |
| `1` | Conformance error (unparseable JSON, malformed `attestation`, failed host binding, forbidden vendor field, or removed `rp_attestation`), or failed attestation under `--require-attestation`. | Fix every entry in `errors` and re-run. |
| `2` | Transport or availability error: document read/fetch failed, or attestation source / JWKS unreachable under `--require-attestation`. | Fix hosting, URL, timeout, or network availability and re-run. |

Stable validator conformance reasons for `attestation` are
`attestation_mode_invalid`, `attestation_uri_invalid`,
`attestation_uri_host_untrusted` (broker mode), `attestation_uri_host_unbound`
(provider mode), and `rp_attestation_removed`. See [Conformance
validator](/protocol/validator/).

## MCP transport and gate errors

Returned with a non-`200` HTTP status from `POST /mcp`, before any tool runs
(`id: null`):

| JSON-RPC code | HTTP | Retryable | Meaning | Next action |
| :--- | :-: | :-: | :--- | :--- |
| `-32001` | `401` | no | Bearer token missing, invalid, expired, or revoked. Response includes `WWW-Authenticate` with `resource_metadata` and `scope`. | Re-run the client's OAuth flow. Do not retry the same token. |
| `-32003` | `403` | no | Human owner account is suspended, email is unverified, or current Master Agent Delegation Agreement is unsigned. | Human resolves the account gate in the Developer Portal. |
| `-32000` | `406` | no | Request did not accept an allowed media type (for example `GET /mcp` without `Accept: text/event-stream`). | Send `POST /mcp` with `Accept: application/json, text/event-stream`. |

## MCP tool errors (35 stable codes)

All 35 codes defined by the broker's MCP error schema:

| Code | Tools | Retryable | Meaning | Next action |
| :--- | :--- | :-: | :--- | :--- |
| `human_suspended` | `identity_signup`, `identity_login` | no | Human owner account is suspended. | Human reinstates the account in the Developer Portal; do not retry. |
| `human_email_unverified` | `identity_signup`, `identity_login` | no | Human owner email address is not verified. | Human verifies their email; do not retry. |
| `master_tos_unsigned` | `identity_signup`, `identity_login` | no | Current Master Agent Delegation Agreement is unsigned. | Human accepts the current agreement in the Developer Portal; do not retry. |
| `agent_revoked` | all 5 tools | no | Bound agent sub-identity is revoked, operator-suspended, or missing from the session. | For revocation, the human reviews the agent in the Developer Portal. Operator suspension is operator-restored only; do not retry or silently create a replacement. |
| `scope_not_granted` | `identity_signup`, `identity_login`, `inbox_read` | no | Agent lacks `tos:accept`, `inbox:read`, or a scope in `requested_scopes`, or `requested_scopes` was passed as `[]`. | Call `identity_whoami` to inspect granted scopes; omit `requested_scopes` to default to discovery `required_scopes`. |
| `tos_version_mismatch` | `identity_signup` | no | Caller-pinned `terms_version` does not match `terms.version` in the fetched discovery document. | Re-read `terms.url` and retry with the current `terms_version`, or omit `terms_version`. |
| `ledger_email_failed` | `identity_signup`, `identity_login` | yes | Delegated acceptance or re-acceptance was recorded, but the terms ledger email dispatch failed. | Retry with the same inputs; the acceptance is reused and only the email is retried. |
| `signup_token_invalid` | `identity_record_signup` | no | `signup_token` is missing, malformed, legacy broker-signed, outside the historical attestation window, or conflicts with an existing receipt. | Obtain an RP-signed Contract E receipt and retry; do not retry the rejected token. |
| `signup_token_not_linked` | `identity_record_signup` | no | Receipt references an acceptance not recorded by this broker for this agent and audience. | Call `identity_signup` for this service first, then record the receipt. |
| `signup_token_ownership_mismatch` | `identity_record_signup` | no | Receipt belongs to a different agent or human owner. | Stop. Use only receipts issued for this authenticated agent. |
| `message_not_found` | `inbox_read` | no | No message with that `message_id` exists for this agent. | Call `inbox_read` without `message_id` to list current message ids. |
| `wait_timeout` | `inbox_read` | yes | No matching inbound email arrived within `wait_seconds` (max `25`). | Retry with a larger `wait_seconds` or `since_seconds_ago`, or list recent messages without `wait_seconds`. |
| `internal_error` | all 5 tools | yes | Unexpected broker, database, or issuance error. | Check `side_effects` and retry; if it persists, report it. |
| `discovery_unreachable` | `identity_signup`, `identity_login` | yes | Relying party discovery document or `terms.url` timed out, returned 5xx, or could not be reached. Nothing was minted. | Retry later when the origin is reachable; never fabricate a document. |
| `discovery_missing` | `identity_signup`, `identity_login` | no | The relying party returned HTTP 404 or 410 for `/.well-known/agent-signup.json` and does not support `agent-identity-protocol` yet. Nothing was minted. | Do not retry. Tell the human owner the service is not yet supported and share the provider prompt kit (`/providers/prompt-kit/`). |
| `discovery_invalid` | `identity_signup`, `identity_login` | no | Discovery document failed schema/rule validation, `terms.url` is unreadable, or an advertised endpoint is not fetchable. | Ask the provider to fix discovery or `terms.url`. |
| `protocol_unsupported` | `identity_signup`, `identity_login` | no | Service advertises an unsupported `protocol` or `protocol_version`. | Stop; the service does not support `agent-identity-protocol` `2.0`. |
| `issuer_not_allowed` | `identity_signup`, `identity_login` | no | This broker is not listed in the provider's `issuer_allowlist`. | Stop; this provider does not accept assertions from this broker. |
| `tos_hash_mismatch` | `identity_signup`, `identity_login` | no | Accepted terms URL or hash no longer matches the provider's current terms. | Re-read `terms.url` and retry with a fresh acceptance, or report the mismatch to the provider. |
| `rp_unverified` | `identity_signup`, `identity_login` | no | Human policy (`verify` or `strict`) requires a verified provider and this service has no valid attestation. | Choose a verified provider or ask the human owner to change the verification policy. |
| `rp_attestation_invalid` | `identity_signup`, `identity_login`, `identity_record_signup` | no | Provider attestation source was malformed, rejected, failed signature/origin/audience/key binding, or the exact historical attestation is unavailable. | Ask the provider to publish a valid attestation, or supply the exact historical `rp_attestation` for a receipt. |
| `rp_attestation_expired` | `identity_signup`, `identity_login` | no | Provider attestation passed `exp` plus 60 seconds of skew. Expired means expired or unverified, never unsafe. | Ask the provider to renew its attestation before retrying. |
| `rp_broker_untrusted` | `identity_signup`, `identity_login`, `identity_record_signup` | no | Attestation issuer is outside the human's and broker's trusted RP-broker list. No JWKS fetch was made. | Ask the human owner to review the broker trust list in `/trust`. |
| `rp_broker_unavailable` | `identity_signup`, `identity_login`, `identity_record_signup` | yes | Attestation source or trusted broker metadata/JWKS was temporarily unavailable or rate limited. | Retry later, honoring any retry hint; never downgrade trust. |
| `rp_suspended` | `identity_signup`, `identity_login` | no | Provider is suspended by its broker (`403 provider_suspended`) or local provider record. | Stop; choose another provider. |
| `rp_blocked` | `identity_signup`, `identity_login` | no | Human owner explicitly blocked this relying party. Checked before any verification mode. | Stop unless the human removes the block in `/trust`. |
| `discovery_source_not_allowed` | `identity_signup`, `identity_login`, `identity_record_signup` | no | Caller passed forbidden `rp_discovery`, `rp_discovery_url`, or `rp_attestation` to `identity_signup`/`identity_login`, or passed `rp_attestation` without `signup_token` to `identity_record_signup`. | Pass only `service` (plus allowed optional fields) to `identity_signup` or `identity_login`, or pass `signup_token` with optional `rp_attestation` to `identity_record_signup`. |
| `rp_attestation_mode_not_allowed` | `identity_signup`, `identity_login` | no | Human `strict` mode requires a broker-managed attestation, but the provider publishes a provider-managed source. | Ask the human to switch to `verify` or the provider to use broker-managed mode. |
| `rp_attestation_revoked` | `identity_signup`, `identity_login` | no | Broker-managed attestation lookup returned `410 attestation_revoked`. | Stop; the provider must obtain a new attestation before retrying. |
| `login_not_supported` | `identity_login` | no | Relying party discovery omits `endpoints.agent_login`. | Do not retry `identity_login`; follow the provider's `SKILL.md` (if returned) or human-facing re-auth flow. |
| `service_relogin_disabled` | `identity_login` | no | Human owner disabled Day-2 re-login for this service in `/trust`. | Do not retry unless the human re-enables re-login for this service in `/trust`. |
| `terms_approval_required` | `identity_login` | no | Human owner enabled strict terms approval in `/settings`, and service terms changed. | Direct the human to `approval_url` (or the emailed approval link), then retry `identity_login` once approved. |
| `auth_md_approval_required` | `identity_signup`, `identity_login` | no | Human approval is required before sharing an ID-JAG assertion with an `auth.md` service (`extra` includes `approval_id`, `approval_url`, `service_origin`, `as_issuer`, `resource`, `op_tos_uri`, `terms_sha256`, `fallback_login_hint`, `expires_at`). | Direct the human to `error.extra.approval_url`, wait for approval, and retry the same tool call. If the service does not trust this broker, guide the human using `error.extra.fallback_login_hint`. |
| `auth_md_reauth_required` | `identity_signup`, `identity_login` | no | Caller passed `require_fresh_auth: true` after `401 login_required`, and the human's `auth_time` is older than 15 minutes (`extra` includes `approval_id`, `approval_url`, `service_origin`, `as_issuer`, `resource`, `expires_at`, `fallback_login_hint`). | Direct the human to `error.extra.approval_url` to confirm fresh re-authentication, then retry the same tool call without `require_fresh_auth`. |
| `auth_md_fallback_available` | `identity_signup`, `identity_login` | no | Detected `auth.md` service does not support or trust ID-JAG assertions from this broker (`extra` includes `fallback_login_hint` and any available service fallback metadata). | Do not retry ID-JAG. Follow `error.next_step` to use `fallback_login_hint` or the service's `claim_token` / `service_auth` / `anonymous` flow. |

`unverified` is not `invalid`. Absence of `attestation` in discovery is
conformant; only `verify` and `strict` policies refuse it. An operator-suspended
agent returns `agent_revoked` with a suspension-specific message and `next_step`.

### Reading `side_effects`

| Tool | Keys in `side_effects` |
| :--- | :--- |
| `identity_whoami` | `{}` |
| `identity_signup` | `acceptance_recorded`, `acceptance_created`, `ledger_email_sent_to_agent`, `ledger_email_forwarded_to_human`, `rp_verification_recorded`, `rp_verification_reused`, plus `assertion_minted` on errors |
| `identity_login` | `terms_reaccepted`, `acceptance_created`, `login_event_recorded`, `ledger_email_sent_to_agent`, `ledger_email_forwarded_to_human`, `new_session_alert_sent`, `rp_verification_recorded`, `rp_verification_reused`, plus `assertion_minted` on errors |
| `identity_record_signup` | `signup_recorded`, `signup_upgraded`, `rp_verification_recorded`, `conflict_flagged` |
| `inbox_read` | `{}` |

An all-`false` `side_effects` object on `identity_signup`, `identity_login`, or
`identity_record_signup` is positive evidence that nothing was written or
emailed.

## Provider handshake errors

Returned by the relying party from `POST endpoints.agent_signup` or `POST
endpoints.agent_login` using the envelope `{ "error": "<code>",
"error_description": "...", "retryable": false }`. When `retryable` is omitted,
infer it from the table below. Normative source: [spec section
7.2](/protocol/specification/#72-error-envelope-and-stable-codes) and [section
7.4–7.5](/protocol/specification/#74-post-endpointsagent_login-handshake--anti-ato-account-resolution-v220).

| Code | HTTP | Retryable | Meaning | Next action |
| :--- | :-: | :-: | :--- | :--- |
| `invalid_request` | `400` | no | Malformed headers or JSON body. | Send `signup_request` or `login_request` verbatim. |
| `invalid_assertion` | `401` | no | Signature, header, `purpose`, or claim structure verification failed. | Mint a fresh assertion with `identity_signup` or `identity_login`. |
| `assertion_expired` | `401` | no | `exp` passed beyond the 60-second clock-skew allowance. | Call `identity_signup` (300s) or `identity_login` (120s) for a fresh assertion. |
| `issuer_not_allowed` | `403` | no | `iss` is not in the provider's `issuer_allowlist`. | Stop; this broker is not accepted by that provider. |
| `audience_mismatch` | `403` | no | `aud` does not equal the provider's published `audience`. | Call `identity_signup` or `identity_login` against the canonical service origin. |
| `insufficient_scope` | `403` | no | `delegation.scopes` misses a `required_scopes` entry. | Check `identity_whoami` and ensure the agent holds all required scopes. |
| `human_unverified` | `403` | no | `human.verified` is not `true`. | Human verifies their email in the Developer Portal. |
| `account_terminated` | `403` | no | Account or agent link at the provider is terminated or suspended (`agent_login`). | Stop; do not retry. |
| `human_action_required` | `202` / `403` | no | Provider requires human step-up (`account_link_required`, `agent_link_required`, `step_up_required`, `billing_required`). | Direct the human owner to `verification_url` (and `user_code` if provided). |
| `account_not_found` | `404` | no | No matching account exists on `endpoints.agent_login`. | Use `identity_signup` first, or check whether a human account needs linking. |
| `assertion_replayed` | `409` | no | `jti` was already used in a conflicting context on `agent_signup`, or already consumed on single-use `agent_login`. | Call `identity_signup` or `identity_login` for a fresh assertion. |
| `tos_hash_mismatch` | `409` | no | `accepted_rp_tos_url` or `accepted_rp_tos_hash` does not match the provider's current terms. | Re-read `terms.url` and call `identity_signup` again so the broker hashes the updated bytes. |
| `terms_reacceptance_required` | `403` / `409` | no | Provider updated terms since the agent's last acceptance (`expected_terms_version`, `terms_url`). | Call `identity_login` with `{ service, reaccept_terms: true }` and resend `login_request`. |
| `rate_limited` | `429` | yes | Caller exceeded the provider's rate limit. | Back off, then retry. |

A `jti` repeated for the **same** agent, account, and service is not a replay; a
conformant provider resolves it idempotently (typically `resolution: "resolved"`).

## Broker provider-verification HTTP codes

Returned by `GET /api/broker/provider-verification` using `{ error,
error_description, code }` (every error sets `Cache-Control: no-store`):

| HTTP | `error` / `code` | Meaning |
| :--- | :--- | :--- |
| `400` | `invalid_request` | Missing, extra, duplicate, or non-canonical `origin` or `audience`. |
| `403` | `provider_suspended` | Provider or origin is suspended. |
| `404` | `attestation_not_found` | Unknown pair, wrong publication mode, unverified origin, or no attestation. Maps to `unverified`. |
| `410` | `attestation_revoked` | Provider or latest attestation is revoked. Maps to `invalid` (`attestation_revoked`). |
| `429` | `rate_limited` | Per-IP rate limit exceeded; honor `Retry-After`. |
| `503` | `broker_unavailable` | Transient database or signing failure. |

| Code | HTTP | Surface | Meaning |

| `invalid_signup_token` | `401` | Contract F | Receipt failed parse, signature, or claim checks. |
| `signup_conflict` | `409` | Contract F / D.2 | Same receipt or report `jti` submitted with a different JWS body. |
| `unauthenticated_report` | `401` | Contract D.2 | Unsigned legacy abuse body; use signed `{ rp_attestation, report }`. |
| `rate_limited` | `429` | Contract F / D.2 / Provider API | Bounded ingestion or request rate exceeded. |
| `rp_broker_unavailable` | `503` | Contract F / D.2 | Transient trusted-broker metadata or JWKS outage; retryable with no write. |

## OAuth 2.1 and registration errors

Returned by `/oauth/authorize`, `/api/oauth/*`, and operator webhooks using RFC
6749 `{ error, error_description }`:

| Code | HTTP | Endpoint | Meaning | Next action |
| :--- | :-: | :--- | :--- | :--- |
| `invalid_client_metadata` | `400` | `/api/oauth/register` | Invalid JSON or client metadata schema failure. | Fix the registration payload. |
| `invalid_redirect_uri` | `400` | `/api/oauth/register`, consent decision | Redirect URI is not loopback HTTP or HTTPS, or does not match the client. | Register and send the exact URI. |
| `invalid_client` | `400` | `/oauth/authorize`, consent decision | `client_id` cannot be resolved. | Register the client or fix the CIMD URL. |
| `unsupported_response_type` | `400` | `/oauth/authorize` | `response_type` is not `code`. | Use `response_type=code`. |
| `invalid_request` | `400` | Authorize, consent decision, token, broker APIs | Malformed payload, missing PKCE/code/token, or inactive/unknown `agent_id`. | Fix the request parameters. |
| `master_tos_required` | `400` | Consent decision | Current Master Agent Delegation Agreement is unsigned and `accept_master_tos` was not `true`. | Accept the agreement in the consent card or Developer Portal. |
| `invalid_grant` | `400` | `/api/oauth/token` | Code unknown/expired/used, PKCE mismatch, refresh token unknown/revoked, inactive/unverified/unsigned human, or inactive bound agent. | Restart the OAuth authorization flow. |
| `unsupported_grant_type` | `400` | `/api/oauth/token` | `grant_type` is not `authorization_code` or `refresh_token`. | Use `authorization_code` or `refresh_token`. |
| `unauthorized` | `401` | Consent decision | No authenticated human session. | Sign in and approve again. |
| `access_denied` | `403` | Consent decision | Human account suspended, an agent on the account is operator-suspended, or human clicked Deny. | Resolve any suspension in the Developer Portal or contact support. |
| `email_verification_required` | `403` | Consent decision | Human email address is not verified. | Verify email before approving an MCP client. |
| `agent_limit_reached` | `403` | Consent decision | Active agent count reached `max_active_agents` (default `2`). | Bind an existing active agent or revoke an unused agent in `/agents`. |
| `server_error` | `500` | `/api/oauth/*` | Broker failed to persist the client, agent, code, or token pair. | Retry later without tight looping. |
| `invalid_webhook_signature` | `401` | `/api/webhooks/resend` | Missing or invalid mail webhook signature. | Operator only; verify webhook secret. |

## Quick decision table

| Situation | Do not | Do |
| :--- | :--- | :--- |
| `tos_version_mismatch` or `tos_hash_mismatch` | Retry the same pinned version or assertion | Re-read `terms.url` and call `identity_signup` with the current version (or omit `terms_version`) |
| `terms_reacceptance_required` | Re-run `identity_signup` for an existing account | Call `identity_login` with `reaccept_terms: true` and resend `login_request` |
| `terms_approval_required` | Retry `identity_login` before approval | Direct the human to `approval_url` (or `/approvals/[id]`), then retry `identity_login` |
| `auth_md_approval_required` / `auth_md_reauth_required` | Mint or retry in a loop without approval | Direct the human to `error.extra.approval_url`, then retry (`auth_md_reauth_required` retries without `require_fresh_auth`) |
| `auth_md_fallback_available` | Keep retrying ID-JAG or claim broker trust | Follow `error.next_step` with `error.extra.fallback_login_hint` or the service's own claim flow |
| `service_relogin_disabled` / `login_not_supported` | Retry `identity_login` unchanged | Ask human to check `/trust` (`service_relogin_disabled`) or follow `SKILL.md` (`login_not_supported`) |
| `human_action_required` | Auto-retry in a loop | Direct the human to `verification_url` (plus `user_code` if provided) |
| `rp_unverified` under `verify` or `strict` | Treat the provider as invalid or unsafe | Ask the human to adjust `/trust` policy or choose a verified provider |
| `rp_attestation_mode_not_allowed` | Force `strict` on a provider-managed source | Ask the human to switch to `verify` or the provider to use broker-managed mode |
| `rp_attestation_revoked` / `rp_suspended` / `rp_blocked` | Retry or fall back to cached state | Stop; policy or provider status blocks signup |
| `rp_broker_unavailable` | Downgrade trust to unverified | Retry later; the gate fails closed |
| `discovery_source_not_allowed` | Pass discovery or attestation objects to `identity_signup` | Call `identity_signup` with `{ service }` only |
| `ledger_email_failed` | Assume acceptance was lost | Retry `identity_signup` with identical inputs; only the email retries |
| `signup_token_invalid` | Substitute a newer attestation or retry unchanged | Obtain a fresh Contract E receipt (and exact historical attestation if needed) |
| `wait_timeout` on `inbox_read` | Poll in a tight loop | Retry with a larger `wait_seconds` (up to `25`) or call `inbox_read` without `wait_seconds` to list recent mail |
| Lost provider credential | Re-run signup | Use the provider's documented recovery path in its `context.url` guide |
| `agent_revoked` | Retry or silently create another agent | Report to the human owner to check `/agents` (or operator if suspended) |
| `-32001` on `/mcp` | Retry the expired or revoked token | Re-run the MCP client's OAuth sign-in flow |
