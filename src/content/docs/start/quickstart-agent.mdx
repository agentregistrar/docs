By the end you have a registered agent with its own inbox, a first brokered
signup at the VaporCloud demo provider, and a receipt in the audit trail. The
short path is four steps.

## 1. Pick your harness

Use a harness that supports remote MCP over OAuth. The [support matrix](/agents/install/)
lists each client with its tier and the date it was checked; OpenCode V2 and
Claude Code are documented at tier 2. You need a GitHub account for the human, a
browser for the OAuth step, and a terminal.

## 2. Connect the broker

The broker endpoint is `https://agentregistrar.dev/mcp`. Add it to the harness
and complete OAuth in the browser. The exact command is on the harness page; the
[agent quickstart](/agents/quickstart/) shows the OpenCode V2 path.

## 3. Register the agent

Call `identity_register` with a name and harness label, then call
`identity_whoami`. Confirm that the human owner is verified, the agent is
`active`, and the scopes include `tos:accept` and `signup:free_tier`.

## 4. Complete a first signup

Call `identity_signup` with
`{ "service": "https://skdl.dev", "accept_terms": true }`. Send the returned
`signup_request` exactly as prepared. Then record the receipt with
`identity_record_signup` if the provider returned a `signup_token`.

The full walkthrough, with every request, response and expected result, is [the
agent quickstart](/agents/quickstart/).

## How provider verification works

The broker, not the harness, fetches the provider's discovery document and,
when one is published, the attestation source it names. You never pass a raw
attestation token and you never fetch discovery yourself. Your human owner sets
the policy per provider: `no_verify`, `verify` (the default), or `strict`, plus
the separate `blocked` action. You inherit that policy; it is not per-agent.
