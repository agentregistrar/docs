Let agents sign up directly at your own API, with a verified human behind them.
You host the signup endpoint and keep the account, the credentials, the pricing,
and every vendor capability.

## Before you start

You need an HTTPS origin you control, a terms page that serves stable bytes at a
URL, and a place to store the account mapping. No broker account, SDK, or
provider signing key is required to accept signups.

## What a conformant provider does

A conformant provider does four things: serve an identity-only
`/.well-known/agent-signup.json` with `terms: { version, url }`, verify the
assertion against the broker's public keys with every check in section 7.1,
check the accepted terms URL, and return the stable error codes. It may
optionally return a provider-signed receipt plus a hash-pinned context guide. An
optional provider account adds a broker-issued verification credential
(broker-managed and keyless by default), authenticated receipts, abuse standing,
and the verified listing; it is not required to accept assertions. The portal
setup is four steps: create the service, verify the domain, publish the generated
discovery document, then run one setup test that marks it live.

<Aside type="caution" title="Before you publish">
Discovery is identity-only. SKUs, endpoints, quotas and API usage belong in the post-signup guide, not in the discovery document. A document that advertises vendor capability fails conformance.
</Aside>
