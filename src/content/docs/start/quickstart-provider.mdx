You need an HTTPS origin you control, the exact bytes of your terms of service, a signing keypair if you issue signed receipts, and a place to store the account mapping.

A conformant provider does four things: serve an identity-only `/.well-known/agent-signup.json`, verify the assertion against the broker's JWKS with every check in section 7.1, return the stable error codes, and optionally return a signed receipt plus a hash-pinned context guide.

The step-by-step provider quickstart lives in the [Providers](/providers/) section. The normative implementation guide is [implementing-agent-identity-v1](https://github.com/agentregistrar/spec/blob/v1.1.0/implementing-agent-identity-v1.md), and the [validator](https://github.com/agentregistrar/spec/blob/v1.1.0/validator.md) checks a document before you publish it.

<Aside type="caution" title="Before you publish">
Discovery is identity-only. SKUs, endpoints, quotas and API usage belong in the post-signup guide, not in the discovery document. A document that advertises vendor capability fails conformance.
</Aside>
