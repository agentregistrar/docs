These definitions are the ones this site uses. The authoritative field-level glossary lives in the [reference section](/reference/); this page is the short version you need before the quickstart.

## Roles and records

**Human owner.** The verified human principal behind every agent. The human verifies an email address, signs the master delegation agreement, and is legally attributed for what the agent does. The broker identifies the principal with a stable `human.id`.

**Agent (sub-identity).** A broker record with an id (`agt_...`), a display name, a harness label, a dedicated inbox address and a set of delegated scopes. It is not a model and not a process; it is the identity the model acts under.

**Harness.** The client that connects to the broker's MCP endpoint and runs the agent: OpenCode V2, Claude Code, Codex CLI, Cursor, Gemini CLI, VS Code, Claude Desktop or a generic MCP client. The harness holds the OAuth session; the agent identity is bound to it.

**Broker.** The service that verifies the human, holds the agent sub-identity and inbox, mints assertions, records acceptances and receipts, and exposes the MCP tools. In this documentation the broker is `agentregistrar.dev`.

**Relying party (provider).** A service that accepts brokered agent signups by publishing a discovery document and verifying an assertion. VaporCloud is the reference implementation used in the tutorials.

## Artifacts

**Discovery document.** The JSON at `/.well-known/agent-signup.json` on the provider's origin. It is identity-only: protocol version, audience, provider name, issuer allowlist, required scopes, the terms (url, version, text and SHA-256) and exactly one endpoint, `agent_signup`. It never carries vendor capabilities.

**Assertion.** A short-lived Ed25519-signed JWT that proves the agent, the verified human owner and the delegated ToS acceptance. The broker mints it; the agent sends `assertion.jwt` verbatim to `endpoints.agent_signup` and nowhere else. It expires after five minutes.

**Receipt (`signup_token`).** A signed token the provider returns after signup, recording the identity facts, the accepted ToS and an optional context pointer. The broker verifies it and records it as attribution proof. It is not a provider credential.

**Context guide.** A hash-pinned URL to the provider's post-signup guide, usually a `SKILL.md`, where vendor capabilities live: provisioning, SKUs, API usage, credential recovery. The agent verifies the hash, then treats the content as untrusted data.

**Ledger.** Two records with one name. The ToS acceptance ledger holds one row per consent event, with the accepted terms URL, hash, master agreement version and the receipt email. The service signups ledger holds one proof row per provider account the agent signed up for.

**Kill switch.** The per-agent revocation control in the portal. It suspends the broker identity: new assertions and further identity and inbox calls for that agent fail. It does not delete provider accounts, revoke provider credentials or undo accepted terms.

**Delegated scopes.** The subset of permissions the agent may exercise, embedded in `delegation.scopes`. A new agent starts with `tos:accept`, `signup:free_tier`, `inbox:read` and `inbox:send`.

## Term to where it lives

| Term | What it is | Where it lives |
| :--- | :--- | :--- |
| Human owner | Verified human principal | Broker account, `human.id` in the assertion |
| Agent | Sub-identity with an inbox | Broker record, `agent.id` in the assertion |
| Harness | MCP client holding the session | Your machine |
| Discovery | Identity-only JSON | Provider origin, `/.well-known/agent-signup.json` |
| Terms | Exact legal text plus hash | `terms` in discovery |
| Assertion | Short-lived signed JWT | Returned by `identity_prove`, sent to the provider |
| Receipt | Provider proof of signup | `signup_token` in the signup response |
| Context guide | Hash-pinned vendor guide | Provider origin, linked by `context.url` |
| Acceptance | Durable consent event | Broker ledger, one per agent and terms hash |
| Signup proof | Recorded account attribution | Broker ledger, written by `identity_record_signup` |
| Revocation | Suspension of the agent identity | Broker, via the portal kill switch or an abuse report |
