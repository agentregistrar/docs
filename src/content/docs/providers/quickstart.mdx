Go from an existing web service to accepting brokered agent signups in four steps: serve a discovery file, add a short JWT verification handler, validate the live document, and verify your domain in the Provider Portal.

No broker account or SDK is required to verify incoming assertions against `https://agentregistrar.dev/.well-known/jwks.json`. Completing domain verification in the [Provider Portal](/providers/portal/) is recommended so clients using the default `verify` policy recognize your service as verified.

<Aside type="tip" title="Using a coding agent?">
Paste [Copy this prompt](/providers/prompt-kit/) into Claude Code, Cursor, Codex, OpenCode, Gemini CLI, or Antigravity CLI to implement the discovery document and signup handler in your repository, then validate the result.
</Aside>

## Prerequisites

- Node 22 or newer with `npm` or `pnpm`.
- A public HTTPS origin for production (`http://localhost` and `http://127.0.0.1` are allowed for local development).
- A stable public page hosting your terms of service at `terms.url` (for example `https://example.com/terms`).

## 1. Publish your discovery document

Serve `GET /.well-known/agent-signup.json` with `Content-Type: application/json`, no authentication, and no redirects. Replace `example.com` and `example-provider` with your own origin and audience identifier.

```json
{
  "protocol": "agent-identity-protocol",
  "protocol_version": "2.0",
  "audience": "example-provider",
  "provider_name": "Example Provider",
  "provider_url": "https://example.com",
  "contact": "security@example.com",
  "issuer_allowlist": ["https://agentregistrar.dev"],
  "required_scopes": ["tos:accept"],
  "terms": {
    "version": "2026.1",
    "url": "https://example.com/terms"
  },
  "endpoints": {
    "agent_signup": "https://example.com/api/signup/agent",
    "agent_login": "https://example.com/api/login/agent"
  }
}
```

`endpoints.agent_login` is optional (`v2.2.0` additive) and enables Day-2 re-authentication without re-running signup. Keep `terms` to `{ version, url }` only. At signup time (and on terms drift during `identity_login`), the broker fetches `terms.url`, hashes the exact UTF-8 response bytes, and writes that digest into `delegation.accepted_rp_tos_hash` alongside `delegation.accepted_rp_tos_version`. When you complete domain verification in the Provider Portal, add the generated `attestation` object to this file.

## 2. Add the JWT signup and Day-2 login handlers

Install `jose` to verify `EdDSA` assertions against the broker's public JWKS:

```bash
npm install jose
```

This ~30-line TypeScript helper checks the JWT signature, issuer, audience, `purpose` (`"signup"` vs `"login"`), expiry and 5-minute max lifetime, `human.verified`, required scopes, and accepted terms URL (plus optional exact hash when `terms.url` serves deterministic UTF-8 bytes):

```ts
import { createRemoteJWKSet, jwtVerify } from "jose";

const ISSUER = "https://agentregistrar.dev";
const AUDIENCE = "example-provider";
const TERMS_URL = "https://example.com/terms";
const TERMS_SHA256: string | undefined = process.env.TERMS_SHA256; // optional, only for deterministic bytes
const jwks = createRemoteJWKSet(new URL(`${ISSUER}/.well-known/jwks.json`));

const norm = (u: string) => u.replace(/\/+$/, "");

export async function verifyAgentAssertion(
  authHeader: string,
  expectedPurpose: "signup" | "login" = "signup",
) {
  if (!authHeader.startsWith("Bearer ")) throw { status: 400, code: "invalid_request" };
  const { payload } = await jwtVerify(authHeader.slice(7), jwks, {
    algorithms: ["EdDSA"],
    typ: "agent-id+jwt",
    clockTolerance: 60,
  });
  if (payload.iss !== ISSUER) throw { status: 403, code: "issuer_not_allowed" };
  if (payload.aud !== AUDIENCE) throw { status: 403, code: "audience_mismatch" };
  if ((payload.exp ?? 0) - (payload.iat ?? 0) > 300) throw { status: 401, code: "invalid_assertion" };
  const purpose = (payload.purpose as string | undefined) ?? "signup";
  if (purpose !== expectedPurpose) throw { status: 401, code: "invalid_assertion" };
  const human = payload.human as { id: string; email: string; verified?: boolean } | undefined;
  const del = payload.delegation as {
    scopes?: string[];
    accepted_rp_tos_url?: string;
    accepted_rp_tos_hash?: string;
    accepted_rp_tos_version?: string;
  } | undefined;
  if (human?.verified !== true) throw { status: 403, code: "human_unverified" };
  if (!del?.scopes?.includes("tos:accept")) throw { status: 403, code: "insufficient_scope" };
  if (!del.accepted_rp_tos_url || norm(del.accepted_rp_tos_url) !== norm(TERMS_URL)) {
    throw { status: 409, code: "tos_hash_mismatch" };
  }
  if (TERMS_SHA256 && del.accepted_rp_tos_hash !== TERMS_SHA256) throw { status: 409, code: "tos_hash_mismatch" };
  return payload;
}
```

In your `POST /api/signup/agent` route:

1. Call `verifyAgentAssertion(request.headers.get("authorization") ?? "", "signup")`. Map `ERR_JWT_EXPIRED` to `401 assertion_expired` and other JOSE failures to `401 invalid_assertion`.
2. Enforce `jti` replay protection and resolve or create the account by `(payload.iss, payload.human.id)`.
3. Return `201` with `resolution: "created"`, any show-once credential, and an optional standardized `handoff` object on first signup, or `200` with `resolution: "resolved"` and no credential on repeats. Always send `Cache-Control: no-store`.
4. Return failures in the stable JSON envelope `{ "error": "<code>", "error_description": "...", "retryable": false }`. See [Error codes](/reference/error-codes/).

In your optional `POST /api/login/agent` route (for returning agents, new laptops, or expired tokens):

1. Call `verifyAgentAssertion(request.headers.get("authorization") ?? "", "login")` and reject replayed `jti` values (`409 assertion_replayed`).
2. Resolve the account in normative anti-ATO order: check `(iss, sub)` first, then broker-created accounts by `(iss, human.id)` (auto-attaching `sub` or returning `202 human_action_required` with `reason: "agent_link_required"`). **Never** auto-link a pre-existing human-registered account by `human.email` alone: return `403 human_action_required` with `reason: "account_link_required"` and a provider `verification_url`. If no account matches, return `404 account_not_found`.
3. Check `delegation.accepted_rp_tos_version` against your current `terms.version`; if stale, return `409 { "error": "terms_reacceptance_required", "expected_terms_version": "...", "terms_url": "..." }`.
4. Mint a fresh **per-session, revocable token** without invalidating active sessions on other devices, and return `200 OK` with `Cache-Control: no-store` and an optional `handoff` (`session`, `mcp`, declarative `cli`, `human_urls` - never include shell commands).

Ready-to-run handlers for Next.js App Router, Hono, Express, and Cloudflare Workers are in [Framework examples](/providers/hosting/).

## 3. Validate your discovery document

Run the `@agentregistrar/discovery@2.2.0` conformance validator against your live URL (or local file during development):

<ValidatorPersonalizer includeProbes />

```bash
npx @agentregistrar/discovery@2.2.0 validate https://example.com/.well-known/agent-signup.json --probe-jwks --json
```

Exit code `0` confirms your document is conformant and every listed issuer serves a valid JWKS. Without an `attestation` object, the validator reports `attestation.status: "unverified"` and still exits `0`.

## 4. Verify your domain and go live

Without domain verification, your service is conformant and unverified: agents configured with `no_verify` can sign up, while agents using the default `verify` policy or `strict` policy will refuse it.

To verify your domain and run a live dry-run test:

1. Create a free provider organization at [agentregistrar.dev/provider/new](https://agentregistrar.dev/provider/new).
2. Add your service (`display_name`, `origin`, `audience`).
3. Complete the **3-step setup wizard** in the [Provider Portal](/providers/portal/): verify your domain via HTTPS file or DNS TXT, paste the generated broker-managed `attestation` block into `/.well-known/agent-signup.json`, and click **Test my setup** to run a synchronous dry-run and mark your service live.
