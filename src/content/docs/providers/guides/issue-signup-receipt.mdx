**Goal:** after an account is created or resolved, optionally return a signed `signup_token` that proves who signed up, for whom, under which terms and when.

The receipt is optional. If you issue one, the broker records it as attribution evidence. The claim set is defined in [spec section 11](/agent-identity/v1/specification/#11-contract-e-identity-facts--the-context-pointer); the field reference is [Receipt and context](/agent-identity/v1/receipt-and-context/).

## What goes in the receipt

| Claim | Value |
| :--- | :--- |
| `iss` | Your service audience. The broker pins it to `service.audience`. |
| `sub` | The agent id (`agt_...`). |
| `aud` | The broker origin, for example `https://agentregistrar.dev`. |
| `jti` | A unique receipt id (`srp_...`). |
| `iat`, `exp` | Issued-at and expiry. The reference implementation uses one year for audit proof. |
| `assertion_jti` | The `jti` of the assertion presented at signup. |
| `service.*` | `audience`, `provider_name`, optional `provider_url`, and an opaque `account_id`. |
| `agent.*` | `id`, `name`, `email`. |
| `human.*` | `id`, `name`, `email`, `verified`. |
| `tos.*` | `version`, `url`, `sha256`, optional `master_tos_version`. |
| `context` | Optional `{ url, sha256 }` pointer to your guide. |
| `signed_up_at` | Unix seconds. |

Do not add `service.instance_sku`, `service.endpoint_url`, a free-form `metadata` object, resource credentials or API usage. The receipt is not a resource inventory. Vendor capability belongs in the context guide.

## Sign it

This fixture signs with a throwaway Ed25519 key so the claims and the JWT shape can be inspected offline. In production, use the signing key registered with the broker for your integration and keep it in a secret store.

Save as `mint-receipt.mjs`:

```js
import { createHash } from "node:crypto";
import { readFileSync } from "node:fs";
import { exportJWK, generateKeyPair, importJWK, jwtVerify, SignJWT } from "jose";

const { publicKey, privateKey } = await generateKeyPair("Ed25519", { extractable: true });
const privateJwk = await exportJWK(privateKey);
const publicJwk = await exportJWK(publicKey);

const guide = readFileSync("SKILL.md");
const context = {
  url: "https://example.com/docs/SKILL.md",
  sha256: "sha256:" + createHash("sha256").update(guide).digest("hex"),
};
const now = Math.floor(Date.now() / 1000);

const claims = {
  iss: "example-rp",
  sub: "agt_01j00000000000000000000000",
  aud: "https://agentregistrar.dev",
  jti: "srp_01j00000000000000000000000",
  iat: now,
  exp: now + 31536000,
  assertion_jti: "jti_01j00000000000000000000000",
  service: {
    audience: "example-rp",
    provider_name: "Example RP",
    provider_url: "https://example.com",
    account_id: "acct_opaque_0001",
  },
  agent: {
    id: "agt_01j00000000000000000000000",
    name: "opencode-agent",
    email: "opencode-agent@agents.example.com",
  },
  human: {
    id: "hum_01j00000000000000000000000",
    name: "Example Human",
    email: "human@example.com",
    verified: true,
  },
  tos: {
    version: "2026.1",
    url: "https://example.com/terms",
    sha256: "sha256:6c18126f93de8d1972589ca94633ca82e76bd9ba1f0592618b0105753f3501d6",
    master_tos_version: "2026.1",
  },
  context,
  signed_up_at: now,
};

const signupToken = await new SignJWT(claims)
  .setProtectedHeader({ alg: "EdDSA", typ: "agent-signup-receipt+jwt", kid: "provider-key-1" })
  .sign(await importJWK(privateJwk, "EdDSA"));

const verified = await jwtVerify(signupToken, await importJWK(publicJwk, "EdDSA"), {
  algorithms: ["EdDSA"],
  audience: "https://agentregistrar.dev",
  typ: "agent-signup-receipt+jwt",
});

console.log(JSON.stringify({
  header: JSON.parse(Buffer.from(signupToken.split(".")[0], "base64url").toString()),
  verified: true,
  sub: verified.payload.sub,
  assertion_jti: verified.payload.assertion_jti,
  account_id: verified.payload.service.account_id,
  context: verified.payload.context,
  claims: Object.keys(verified.payload).sort(),
}, null, 2));
```

## Return it and record it

Return the token in the signup response as `signup_token`, next to the credentials:

```json
{
  "resolution": "created",
  "account_id": "acct_opaque_0001",
  "api_key": "sk_live_<show-once>",
  "signup_token": "<compact JWS>",
  "context": {
    "url": "https://example.com/docs/SKILL.md",
    "sha256": "sha256:a3307e1b3904c7671f341730017f21bed656a85241b645c854b4f2887e7976ac"
  }
}
```

The agent records it with `identity_record_signup`, or you deliver it to the broker through Contract F:

```bash
SIGNUP_TOKEN="<compact JWS from the previous step>"
curl -sS -X POST https://agentregistrar.dev/api/broker/signup-receipt \
  -H 'Content-Type: application/json' \
  -d "{\"signup_token\":\"$SIGNUP_TOKEN\"}"
```

A token the broker cannot verify is rejected. Recorded on 2026-10-21 with a deliberately invalid value:

```text
HTTP 401
{"error":"invalid_signup_token","error_description":"The signup token is invalid or could not be verified."}
```

Contract F accepts `{ "signup_token": "..." }` and verifies the signature, `aud`, `typ`, `iss`, the agent and the human before writing an idempotent proof row. The response fields are `ok`, `signup_id`, `signup_token_jti`, `assertion_jti`, `agent_id`, `service_audience`, `provider_account_id`, `human_email_shared`, and the nullable `context_url` / `context_sha256`. Those fields are defined in the broker's shared schema; this page does not execute a live receipt because that requires a real agent signup.

## Resolve and retry

- Create the account once. On a repeat, resolve it and return `resolution: "resolved"`.
- On resolve, omit the provider credential. Do not send duplicate welcome or legal mail.
- You may mint a fresh `signup_token` on resolve so a dropped-response retry can still record the receipt.
- The receipt `jti` identifies the receipt, not the account. Do not use it as the account key.
- `service.account_id` is opaque. It may be a database id or a handle. It must not encode SKUs, regions or resource state.

## Verify your work

- [ ] The JWT header is `alg: EdDSA` and `typ: agent-signup-receipt+jwt`.
- [ ] The claims match Contract E, with no vendor resource fields.
- [ ] `iss` equals `service.audience` and `aud` is the broker origin.
- [ ] `assertion_jti` is the `jti` of the assertion you verified.
- [ ] `context.url` and `context.sha256` match the guide you actually serve, and the domain matches the signup endpoint.
- [ ] A resolve returns no credential and no duplicate mail.
