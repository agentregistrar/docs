Accept a signup request only when the compact `EdDSA` JWT in `Authorization: Bearer <jwt>` passes every signature, claim, terms, and replay check in [spec section 7.1](/protocol/specification/#7-assertion--agent_signup-handshake).

Verifying incoming assertions requires no broker account and no SDK: you fetch the issuer's public JWKS from `GET <iss>/.well-known/jwks.json` and check the signed claims locally. See [Assertion claims](/protocol/assertion-claims/) for the full payload schema and [Error codes](/reference/error-codes/) for the complete error envelope.

## Verification checklist and error codes

Map each failed check to its fixed error code in `{ "error": "<code>", "error_description": "...", "retryable": false }`:

| Check | Requirement | Failure status and code |
| :--- | :--- | :--- |
| Bearer header | `Authorization: Bearer <jwt>` is present. | `400 invalid_request` |
| JOSE header and signature | `alg` is `EdDSA`, `typ` is `agent-id+jwt`, key selected by `kid` from `<iss>/.well-known/jwks.json`. Reject `jku` and `x5u` headers. | `401 invalid_assertion` |
| Expiry | `exp` has not passed (at most 60 seconds of clock skew). | `401 assertion_expired` |
| Lifetime | `exp - iat` is positive and at most 300 seconds (5 minutes). | `401 invalid_assertion` |
| Issued at | `iat` is not more than 60 seconds in the future. | `401 invalid_assertion` |
| Issuer | `iss` matches an exact entry in your `issuer_allowlist`. | `403 issuer_not_allowed` |
| Audience | `aud` matches your published `audience` exactly. | `403 audience_mismatch` |
| Scopes | `delegation.scopes` includes every entry in `required_scopes` (at minimum `tos:accept`). | `403 insufficient_scope` |
| Human verification | `human.verified === true`. | `403 human_unverified` |
| Terms binding | `delegation.accepted_rp_tos_url` matches your current `terms.url` (trailing slashes normalized). Also compare `delegation.accepted_rp_tos_hash` when `terms.url` serves deterministic UTF-8 bytes. | `409 tos_hash_mismatch` |
| Replay and idempotency | Unique account key `(iss, human.id)` (or `(iss, agent.id)`). Same `jti` for the same account resolves (`200`, `resolution: "resolved"`, no credential). Same `jti` in a conflicting context is rejected. | `409 assertion_replayed` |

If a JWKS fetch fails transiently, return a retryable `503` response rather than caching a failure or bypassing verification. Always read identity and delegation claims strictly from the verified JWT payload; never trust unverified identity fields in the request body.

## Reference verifier

Save as `verify.mjs` (`npm install jose`):

```js
import { createRemoteJWKSet, decodeProtectedHeader, jwtVerify } from "jose";

const MAX_LIFETIME_SECONDS = 300;
const CLOCK_TOLERANCE_SECONDS = 60;

function normalizeUrl(value) {
  return value.replace(/\/+$/, "");
}

export async function verifyAssertion(jwt, config) {
  const fail = (code, description) => {
    const error = new Error(description);
    error.code = code;
    throw error;
  };

  let header;
  try {
    header = decodeProtectedHeader(jwt);
  } catch {
    fail("invalid_assertion", "Malformed JOSE header");
  }
  if ("jku" in header || "x5u" in header) {
    fail("invalid_assertion", "Remote key headers jku and x5u are not allowed");
  }

  let payload;
  try {
    const jwks = createRemoteJWKSet(new URL(config.jwksUrl), {
      timeoutDuration: 5000,
      cooldownDuration: 30000,
    });
    const result = await jwtVerify(jwt, jwks, {
      algorithms: ["EdDSA"],
      clockTolerance: CLOCK_TOLERANCE_SECONDS,
      typ: "agent-id+jwt",
    });
    payload = result.payload;
  } catch (error) {
    if (error.code === "ERR_JWT_EXPIRED") {
      fail("assertion_expired", "Assertion has expired");
    }
    fail("invalid_assertion", "Signature or JOSE header verification failed");
  }

  if (!config.issuerAllowlist.includes(payload.iss)) {
    fail("issuer_not_allowed", "Issuer is not in issuer_allowlist");
  }
  if (payload.aud !== config.audience) {
    fail("audience_mismatch", "Assertion audience does not match");
  }
  const now = Math.floor(Date.now() / 1000);
  if (typeof payload.iat !== "number" || typeof payload.exp !== "number") {
    fail("invalid_assertion", "Assertion must carry numeric iat and exp claims");
  }
  if (payload.exp <= payload.iat) {
    fail("invalid_assertion", "Assertion lifetime must be positive");
  }
  if (payload.iat > now + CLOCK_TOLERANCE_SECONDS) {
    fail("invalid_assertion", "Assertion was issued too far in the future");
  }
  if (payload.exp - payload.iat > MAX_LIFETIME_SECONDS) {
    fail("invalid_assertion", "Assertion lifetime exceeds 300 seconds");
  }

  const scopes = payload.delegation?.scopes ?? [];
  if (!config.requiredScopes.every((scope) => scopes.includes(scope))) {
    fail("insufficient_scope", "Delegated scopes do not cover required_scopes");
  }
  if (payload.human?.verified !== true) {
    fail("human_unverified", "The human owner is not verified");
  }

  const acceptedUrl = payload.delegation?.accepted_rp_tos_url;
  if (typeof acceptedUrl !== "string" || normalizeUrl(acceptedUrl) !== normalizeUrl(config.termsUrl)) {
    fail("tos_hash_mismatch", "Accepted terms URL does not match the published terms URL");
  }
  if (config.termsSha256 !== undefined && payload.delegation?.accepted_rp_tos_hash !== config.termsSha256) {
    fail("tos_hash_mismatch", "Accepted terms hash does not match the served terms bytes");
  }

  const accountKey = `${payload.iss}:${payload.human.id}`;
  const previous = config.seenJti.get(payload.jti);
  if (previous !== undefined && previous !== accountKey) {
    fail("assertion_replayed", "Assertion id was used in a conflicting context");
  }
  config.seenJti.set(payload.jti, accountKey);

  return { claims: payload, resolution: previous === undefined ? "created" : "resolved" };
}
```

In production, back `seenJti` and your account lookup with database unique constraints so concurrent requests and restarts remain idempotent.

## Test locally with a synthetic fixture

Providers never mint assertions or hold a broker private key in production. This offline fixture generates a throwaway Ed25519 key pair so you can test every verifier branch locally.

```bash
mkdir provider-verify
cd provider-verify
npm init -y
npm pkg set type=module
npm install jose
```

Save as `mint-test-assertion.mjs`:

```js
import { createHash } from "node:crypto";
import { writeFileSync } from "node:fs";
import { exportJWK, generateKeyPair, SignJWT } from "jose";

const { publicKey, privateKey } = await generateKeyPair("Ed25519");
const publicJwk = await exportJWK(publicKey);

const jwks = { keys: [{ ...publicJwk, kid: "test-key-1", alg: "EdDSA", use: "sig" }] };
writeFileSync("jwks.json", JSON.stringify(jwks, null, 2) + "\n");

const termsText = "Example Provider Terms of Service v2026.1";
const tosHash = "sha256:" + createHash("sha256").update(termsText, "utf8").digest("hex");
const now = Math.floor(Date.now() / 1000);

const jwt = await new SignJWT({
  agent: { id: "agt_test", name: "test-agent", email: "test-agent@agents.example", harness: "test" },
  human: { id: "hum_test", name: "Test Human", email: "human@example.com", verified: true },
  delegation: {
    master_tos_version: "2026.1",
    accepted_rp_tos_url: "https://example.com/terms",
    accepted_rp_tos_hash: tosHash,
    accepted_at: now,
    scopes: ["tos:accept"],
  },
})
  .setProtectedHeader({ alg: "EdDSA", kid: "test-key-1", typ: "agent-id+jwt" })
  .setIssuer("https://agentregistrar.dev")
  .setSubject("agt_test")
  .setAudience("example-provider")
  .setJti("jti_test_0001")
  .setIssuedAt(now)
  .setExpirationTime(now + 300)
  .sign(privateKey);

writeFileSync("assertion.jwt", jwt + "\n");
console.log("wrote jwks.json and assertion.jwt");
```

Save as `serve-jwks.mjs`:

```js
import { createServer } from "node:http";
import { readFileSync } from "node:fs";

const jwks = readFileSync("jwks.json", "utf8");
createServer((_req, res) => {
  res.writeHead(200, { "content-type": "application/json" });
  res.end(jwks);
}).listen(3015, "127.0.0.1", () => {
  console.log("jwks on http://127.0.0.1:3015/.well-known/jwks.json");
});
```

Save as `check.mjs`:

```js
import { createHash } from "node:crypto";
import { readFileSync } from "node:fs";
import { verifyAssertion } from "./verify.mjs";

const jwt = readFileSync("assertion.jwt", "utf8").trim();
const seenJti = new Map();
const config = {
  jwksUrl: "http://127.0.0.1:3015/.well-known/jwks.json",
  issuerAllowlist: ["https://agentregistrar.dev"],
  audience: "example-provider",
  requiredScopes: ["tos:accept"],
  termsUrl: "https://example.com/terms",
  termsSha256:
    "sha256:" +
    createHash("sha256").update("Example Provider Terms of Service v2026.1", "utf8").digest("hex"),
  seenJti,
};

for (const attempt of [1, 2]) {
  try {
    const result = await verifyAssertion(jwt, config);
    console.log(JSON.stringify({ attempt, outcome: "ok", resolution: result.resolution }));
  } catch (error) {
    console.log(JSON.stringify({ attempt, outcome: "error", code: error.code }));
  }
}
```

Run the generator, start the local JWKS server in one terminal, and run `check.mjs` in another:

```bash
node mint-test-assertion.mjs
node serve-jwks.mjs
```

```bash
node check.mjs
```

Expected output:

```text
{"attempt":1,"outcome":"ok","resolution":"created"}
{"attempt":2,"outcome":"ok","resolution":"resolved"}
```

You can also point any handler in [Framework examples](/providers/hosting/) at the local fixture `http://127.0.0.1:3015/.well-known/jwks.json` using `JWKS_URL_OVERRIDE` to test create and resolve over HTTP.

## JWKS caching and key rotation

- **Pin the JWKS path to your allowlisted issuer:** Always fetch `GET <iss>/.well-known/jwks.json` (never from `jku`, `x5u`, or a request parameter).
- **Cache with refresh on unknown `kid`:** Cache keys for minutes rather than indefinitely, and refresh once when an assertion presents an unknown `kid`. Do not hard-code key IDs such as `broker-key-1`.
- **Bound network calls:** Apply a timeout (for example 5 seconds) and a response size cap so a slow JWKS endpoint cannot stall your signup route.
- **Revocation timing:** Agent revocation and suspension are enforced by the broker at minting time. Existing short-lived assertions remain cryptographically valid until `exp` (at most 5 minutes).
