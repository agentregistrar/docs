The normative rules are in [the specification](/agent-identity/v1/specification/#5-discovery-document-reference-identity-only); this page does not replace them.

Unknown additive fields must be ignored by consumers. Producers should put non-capability metadata under `extensions.<reverse-dns-namespace>` so typos stay visible. Moving a vendor capability under `extensions` does not make it conformant.

## Forbidden fields

These must not appear at any nesting depth, including under `extensions`:

| Forbidden surface | Examples |
| :--- | :--- |
| Catalogs and commercial surface | `instance_catalog`, SKUs, pricing tiers, free-tier quotas, product specs |
| Provisioning and resource endpoints | `endpoints.provision`, resource endpoints, instance lifecycle |
| Legacy signup endpoints | `endpoints.email_signup`, `endpoints.verify_otp` |
| Broker receipt callback | `endpoints.broker_signup_receipt` |
| Credentials and API usage | resource credentials, vendor API or SDK usage metadata |

A document is a parameter document, not a capability catalog. Vendor capabilities belong in the post-signup context guide. See [Scope boundaries](/agent-identity/v1/scope-boundaries/) and the normative [5.3](/agent-identity/v1/specification/#53-forbidden-fields-vendor-capability-surface).

## Terms text and hash

- Hash the exact UTF-8 bytes of `terms.text`. Do not normalize line endings, trim whitespace or extract text from HTML.
- `terms.text` must be the complete agreement. A summary makes the hash ambiguous.
- The agent recomputes the hash before calling the broker; the broker verifies the accepted text against the hash it records.
- The relying party rejects an assertion whose `delegation.accepted_rp_tos_hash` is not the currently advertised `terms.sha256`.
- When the terms change, publish the new text and hash before accepting new signups. A bounded grace period for in-flight assertions is a relying-party policy documented outside discovery; it should not exceed 24 hours.

See [ToS binding](/agent-identity/v1/specification/#6-tos-binding) and [Re-acceptance](/agent-identity/v1/specification/#61-re-acceptance).

## Minimal conformant example

This document contains only the required identity fields. Its `terms.sha256` is the real SHA-256 of the `terms.text` value shown. It passes the `v1.1.0` validator in file mode with zero errors and zero warnings.

```json
{
  "protocol": "agent-identity-v1",
  "audience": "example-rp",
  "provider_name": "Example RP",
  "issuer_allowlist": ["https://agentregistrar.dev"],
  "required_scopes": ["tos:accept"],
  "terms": {
    "version": "2026.1",
    "url": "https://example.com/terms",
    "sha256": "sha256:05435fa3eaee7f3534b4a771ab2328d66d33f712f3534b29e9035717c246d953",
    "text": "Example RP Terms of Service. The agent acts for a verified human owner, and the human owner is bound by these terms."
  },
  "endpoints": {
    "agent_signup": "https://example.com/api/signup/agent"
  }
}
```

The example is illustrative. Replace the audience, URLs, scopes and terms with the service's own values, and recompute the hash. The allowlist entry is the live broker origin (`https://agentregistrar.dev`); a provider that accepts a different broker lists that broker's origin instead.

## Known limits

- The JSON Schema enforces the `sha256:` format, not digest equality. The digest check is a cross-field rule in the shared Zod schema and the conformance validator.
- Discovery conformance is cheap to publish. A valid document is not a statement about the service's security, uptime or product.
- The document is not signed in v1. Trust comes from TLS, the issuer allowlist, issuer-hosted JWKS and the signed assertion.
- Consumers must ignore unknown additive fields, so a producer can add an identity field without a schema change. The validator warns on unknown top-level fields; warnings do not fail conformance.

## Verify

- Fetch the published document and confirm `Content-Type: application/json`.
- Recompute `terms.sha256` from the exact bytes of `terms.text`.
- Run the [validator](/agent-identity/v1/validator/) against the document.
- Confirm no forbidden field appears at any depth, including under `extensions`.
