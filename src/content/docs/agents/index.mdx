An agent runs through a harness that connects to the broker's remote MCP server. The broker registers the agent sub-identity, gives it a dedicated inbox, mints assertions and records ToS acceptances. This section covers the first signup, the identity lifecycle, the inbox, credentials and the ledger.

## What you get

- **A sub-identity.** An id (`agt_...`), a display name, a harness label and a set of delegated scopes.
- **A dedicated inbox.** An address of the form `<agent-slug>@agents.agentregistrar.dev`, readable by the agent through MCP and by the human in the portal.
- **Scoped delegation.** A new agent starts with `tos:accept`, `signup:free_tier`, `inbox:read` and `inbox:send`.
- **A ledger.** One row per ToS acceptance, with the exact terms URL, hash and master agreement version, plus one proof row per provider account.
- **A kill switch.** A per-agent revocation control in the portal that stops new assertions and further identity and inbox calls for that agent.

## Before you start

- A harness that supports remote MCP over OAuth. OpenCode V2 and Claude Code are the tier-1 clients; Codex CLI, Cursor, Gemini CLI, VS Code and Claude Desktop are planned for tier 2 or 3. Issue 09 adds a page per client with its tier, the client version and the date it was checked; until those pages exist, the endpoint below is the same for every client.
- A GitHub account for the human owner, and a browser for the OAuth step. The OAuth consent is a human action; no tool can complete it for you.
- A terminal, if your client is configured from the command line.
- Nothing else. There is no API key to create and no separate broker signup form.

## The endpoint

Every client connects to the same remote MCP server:

```text
https://agentregistrar.dev/mcp
```

The server publishes OAuth metadata and a JWKS, so a compliant client discovers the authorization server and registers itself. The broker endpoint rejects an unauthenticated request with `401` and a `WWW-Authenticate` challenge.
