Every coding tool connects to the same remote MCP server using standard OAuth 2.1 (PKCE `S256`). There is no broker API key to copy and no separate OAuth client ID to register: the broker advertises both Client ID Metadata Documents (CIMD) and Dynamic Client Registration (DCR).

```text
https://agentregistrar.dev/mcp
```

Use the exact URL above with no trailing slash, and never add a static `Authorization` header (a manual header bypasses OAuth discovery).

## Pick your coding tool

<Tabs syncKey="harness">
  <TabItem label="Claude Code">
    Add the server from your terminal:

    ```bash
    claude mcp add --transport http agentregistrar https://agentregistrar.dev/mcp
    ```

    The default scope is `local`. Add `--scope user` to enable it across every project, or `--scope project` to write a shared `.mcp.json`:

    ```json
    {
      "mcpServers": {
        "agentregistrar": {
          "type": "http",
          "url": "https://agentregistrar.dev/mcp"
        }
      }
    }
    ```

    Keep `"type": "http"` in hand-written `.mcp.json` files (omitting `type` makes Claude Code treat the entry as stdio). Then run `/mcp` inside Claude Code (or `claude mcp login agentregistrar` from a shell) to complete OAuth sign-in in your browser. If you need a fixed loopback port, pass `--callback-port 8080` when adding the server.

    To reset stored credentials, use **Clear authentication** inside `/mcp`, or run `claude mcp remove agentregistrar`.
  </TabItem>
  <TabItem label="Cursor">
    Create `.cursor/mcp.json` in your project (or `~/.cursor/mcp.json` for all projects):

    ```json
    {
      "mcpServers": {
        "agentregistrar": {
          "url": "https://agentregistrar.dev/mcp"
        }
      }
    }
    ```

    Reload the Cursor window, open MCP settings under **Customize**, start `agentregistrar`, and choose to authenticate in your browser. Cursor uses `http://localhost:8787/callback` on desktop and `https://www.cursor.com/agents/mcp/oauth/callback` on web surfaces; the broker accepts both under DCR and CIMD.

    Check the **Output** panel (`MCP Logs`) if tools do not appear. Remove and re-add the entry to force a fresh OAuth registration.
  </TabItem>
  <TabItem label="OpenCode">
    Add the server globally (or omit `--global` for the current project):

    ```bash
    opencode mcp add agentregistrar --global --url https://agentregistrar.dev/mcp
    ```

    This writes the V2 `mcp.servers` shape to `opencode.json`:

    ```json
    {
      "mcp": {
        "servers": {
          "agentregistrar": {
            "type": "remote",
            "url": "https://agentregistrar.dev/mcp"
          }
        }
      }
    }
    ```

    Authenticate by running `opencode mcp auth agentregistrar` or `/mcps` inside OpenCode. OpenCode discovers CIMD first and falls back to DCR. Tools appear prefixed with the server name (`agentregistrar_identity_whoami`, or `tools.agentregistrar.identity_whoami` in Code Mode).

    To clear stored tokens, run `opencode mcp logout agentregistrar`.
  </TabItem>
  <TabItem label="Codex CLI">
    Add the server and start OAuth login:

    ```bash
    codex mcp add agentregistrar --url https://agentregistrar.dev/mcp
    codex mcp login agentregistrar
    ```

    This writes `[mcp_servers.agentregistrar]` to `~/.codex/config.toml` (or `.codex/config.toml` in a trusted project):

    ```toml
    [mcp_servers.agentregistrar]
    url = "https://agentregistrar.dev/mcp"
    ```

    Codex prefers CIMD and falls back to DCR. If registration fails during login, force DCR explicitly:

    ```bash
    codex mcp login agentregistrar --oauth-client-registration dcr
    ```

    To disconnect, re-run `codex mcp login agentregistrar` or remove the `[mcp_servers.agentregistrar]` section from `config.toml`.
  </TabItem>

    1. Open ChatGPT settings and enable **Developer mode** under your account or workspace connector settings.
    2. Open the **Apps / Connectors** panel, click **+**, and choose **Add custom MCP server**.
    3. Enter the name `Agent Registrar`, connection URL `https://agentregistrar.dev/mcp`, and description `Brokered identity, delegated terms acceptance, signup receipt recording, and per-agent email inbox reads under a verified human owner.`
    4. Set **Authentication** to **OAuth** (ChatGPT discovers the OAuth endpoints automatically from `/.well-known/oauth-protected-resource` and `/.well-known/oauth-authorization-server` and registers via Dynamic Client Registration).
    5. Save the connector and click **Connect / Sign in** to approve browser OAuth consent and bind an agent.
  </TabItem>
  <TabItem label="Generic MCP client">
    Any compliant MCP client connects to `https://agentregistrar.dev/mcp` over Streamable HTTP (`POST` JSON-RPC 2.0 with `Accept: application/json, text/event-stream` and `Authorization: Bearer <token>`):

    1. An unauthenticated request returns `401` with `WWW-Authenticate: Bearer resource_metadata="https://agentregistrar.dev/.well-known/oauth-protected-resource"`.
    2. Fetch `GET https://agentregistrar.dev/.well-known/oauth-protected-resource` and `GET https://agentregistrar.dev/.well-known/oauth-authorization-server`.
    3. Register via CIMD (send your metadata document URL as `client_id`) or Dynamic Client Registration (`POST https://agentregistrar.dev/api/oauth/register` with loopback `http://127.0.0.1` / `http://localhost` or `https://` redirect URIs).
    4. Open `/oauth/authorize` with PKCE `S256`, exchange the code at `/api/oauth/token`, and call `/mcp`.

    Quick discovery check with `curl`:

    ```bash
    curl -sS -D - -o /dev/null https://agentregistrar.dev/mcp
    curl -sS https://agentregistrar.dev/.well-known/oauth-authorization-server
    ```

## Complete browser OAuth and bind an agent

Every tool follows the same browser consent flow on `https://agentregistrar.dev/oauth/authorize`:

1. **Sign in and verify:** if you are not signed in yet, you are routed through GitHub sign-in (`/login`) and email verification (`/onboarding/verify-email`), then returned to the exact same consent screen.
2. **Master Agreement (if unsigned):** if you have not signed the current Master Agent Delegation Agreement yet, you can review and accept it inline right on the consent page.
3. **Bind an agent:** under **Agent identity**, either:
   - **Create a new agent** with a display name (up to your active agent quota, default `2` active agents; unlimited if your account quota is unset); or
   - **Connect to an existing active agent** so this coding tool shares that agent's exact `agt_...` identity and `@agents.agentregistrar.dev` inbox.
4. **Approve:** click **Approve & Connect Harness**. The browser redirects back to your tool's callback URL and stores the OAuth token locally.

<Aside type="caution" title="When approval is blocked">
If you have already reached your active agent limit (for example `2 of 2 active`), choose **Connect to an existing active agent** or revoke an unused agent in `/dashboard` first. If any agent on your account is currently **suspended** by the broker operator following a verified abuse report, new OAuth connections cannot be approved until the suspension is resolved.
</Aside>

## Confirm the four tools with `identity_whoami`

Once connected, verify your tool lists exactly four broker tools:

- `identity_whoami`
- `identity_signup`
- `identity_record_signup`
- `inbox_read`

Ask your coding tool:

```text
Use the agentregistrar MCP server. Call identity_whoami with no arguments and show me the agent ID, email address, and scopes.
```

You should see the agent you created or selected during OAuth consent, along with `status: "active"` and default scopes `["tos:accept", "signup:free_tier", "inbox:read"]`.

Hitting a connection or OAuth error? See [Agent troubleshooting](/agents/troubleshooting/).
