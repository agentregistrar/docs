Gemini CLI is now an enterprise and paid-API-key path; use Antigravity if you
are starting fresh.

## Before you start

- Antigravity installed, with a browser for the OAuth step.
- A verified human account with the master delegation agreement signed. See the
  [agent quickstart](/agents/quickstart/).
- The server URL has no trailing slash: `https://agentregistrar.dev/mcp`.

Antigravity reads MCP servers from one `mcp_config.json` schema across the app,
the IDE and the CLI. The global file is `~/.gemini/config/mcp_config.json`; a
workspace file is `.agents/mcp_config.json`.

## Add the server

Add this entry to the global or workspace file:

```json
{
  "mcpServers": {
    "agentregistrar": {
      "serverUrl": "https://agentregistrar.dev/mcp"
    }
  }
}
```

`serverUrl` is the remote Streamable HTTP transport. The legacy `httpUrl` field
from Gemini CLI is not supported, and `url` is for a different transport. Do not
add an `Authorization` header: OAuth supplies the credential, and a configured
header bypasses the client's discovery flow.

You can also open `/mcp` in the CLI or the MCP Servers section in the IDE and add
the server there. The file is the source of truth either way.

## Authorize

Open `/mcp` in the CLI, or Settings > Customizations > Installed MCP Servers in
the app, and choose Authenticate next to `agentregistrar`.

Antigravity handles OAuth 2.0 with PKCE for remote servers that support Client ID
Metadata Documents (CIMD) or Dynamic Client Registration (DCR); this broker
supports both. The client discovers the broker's protected-resource metadata and
authorization server, opens a browser, and stores the token in
`~/.gemini/antigravity/mcp_oauth_tokens.json`.

If the client asks for a manual OAuth client, register
`antigravity.google/oauth-callback` as the redirect URI with the broker and put
the client credentials in the entry's `oauth` block. The automatic path needs no
manual client.

## Verify the connection

Open `/mcp` and confirm the server is connected. It should expose the nine broker
tools: `identity_register`, `identity_whoami`, `identity_signup`,
`identity_prove`, `identity_record_signup`, `inbox_list`, `inbox_read`,
`inbox_wait_for_email` and `inbox_send`.

If the server connects with no tools, open the connection log in `/mcp` and
reload. Check that the URL has no trailing slash and that the entry uses
`serverUrl`.

## First call

Ask the agent to call `identity_register` with
`{"name": "antigravity-agent", "harness": "antigravity-cli"}`, then call
`identity_whoami` with no arguments and show the result.

`identity_register` creates the agent and binds it to the OAuth session;
`identity_whoami` returns the same agent. Registration is idempotent: the agent
bound to the token is returned whatever name you pass later, so a different name
needs a new OAuth session.

## Troubleshooting

| Symptom | Cause | Fix |
| :--- | :--- | :--- |
| The server is missing from `/mcp` | The entry is in a workspace file that is not open, or the JSON is invalid | Check `~/.gemini/config/mcp_config.json` and `.agents/mcp_config.json`; fix the JSON and reload |
| The server shows a transport error | The entry used `httpUrl` or `url` instead of `serverUrl` | Change the property to `serverUrl` and reconnect |
| Authentication completes but tools stay missing | The token was stored for another account, or discovery failed | Re-authenticate after signing out, or delete `~/.gemini/antigravity/mcp_oauth_tokens.json` and try again |
| Tools are listed but calls fail with `401` | The token expired and the refresh did not run | Re-authenticate in `/mcp` |
| The server is disconnected after a restart | It was added to a workspace you are not in | Move it to the global file or open that workspace |

## Remove and reset

Delete the `agentregistrar` entry from `mcp_config.json`, then reload `/mcp`.
Removing the server does not necessarily delete the stored token; delete
`~/.gemini/antigravity/mcp_oauth_tokens.json` if you need a clean sign-in as
another account.
