Agent Registrar proves identity and records that a signup happened. It is **not** a credential vault, never sees or stores provider API keys, and cannot recover a lost key for you.

## What Agent Registrar does not store

- No provider API keys, bearer tokens, passwords, or OAuth secrets returned by third-party services.
- No provider resource inventory or billing details.
- No mechanism to exchange a `signup_token` receipt for a provider credential.

A `signup_token` is a provider-signed proof that an account was created or resolved under a recorded terms acceptance. It is an audit artifact for `/activity`, not an API credential.

## Save the credential at handoff

When a provider returns a show-once API key during signup (`resolution: "created"`), store it immediately before redacting, summarizing, or ending the agent session. `identity_record_signup` reinforces this rule in its `handoff` block on every response:

```json
{
  "handoff": {
    "broker_stores_credentials": false,
    "store_credentials_now": true,
    "recovery": "provider-owned",
    "context_url": "https://skdl.dev/docs/SKILL.md",
    "note": "Persist any provider credential in a secure store before redacting, summarizing, or ending the task. The Broker never stores provider credentials. If a credential is lost, use the provider's recovery path (see its guide); do not re-run signup to recover it."
  }
}
```

- **Where to store it:** a secret manager, password manager, or the runtime secret store configured for your project.
- **Where never to rely on it:** chat transcripts, agent inbox emails, `/activity`, task summaries, or committed source files. If a credential lands in a shared transcript or repository, treat it as exposed and rotate it.
- **Order of operations:** save to your secret store first, then redact or summarize the session.

## Never re-run signup to recover a lost key

If you call `identity_signup` and POST to a provider's signup endpoint a second time for an existing account, a conformant provider returns `resolution: "resolved"` with **no credential**. That is intentional: show-once keys are never replayed by the signup endpoint.

Instead, follow the recovery or rotation path in the provider's post-signup guide (`context.url`).

### Example: rotating a VaporCloud key

VaporCloud's guide (`https://skdl.dev/docs/SKILL.md`) documents key rotation using a fresh five-minute signed identity token from `identity_signup`:

1. Call `identity_signup` with `{ "service": "https://skdl.dev" }`. Because your agent already accepted VaporCloud's current terms, the broker reuses that acceptance (no duplicate terms email is sent) and mints a fresh five-minute token.
2. Send that token from `signup_request.headers.Authorization` to VaporCloud's rotation endpoint:

```bash
export ASSERTION_JWT="<fresh token from identity_signup>"
curl -sS -X POST https://skdl.dev/api/account/rotate-key \
  -H "Authorization: Bearer $ASSERTION_JWT"
```

```json
{
  "account_id": "7b0c9e2a-4f1d-4c8a-9e37-2d5b6a1c8f04",
  "vapor_api_key": "vc_live_<32 hex>",
  "rotated_at": "2026-11-22T10:20:00.000Z"
}
```

VaporCloud invalidates the previous key immediately and returns the new show-once key. Save the new key right away.

## When a provider has no rotation API

Not every provider exposes an automated rotation endpoint in its guide. If a credential is lost and no API rotation path is documented:

1. Stop retrying signup; `resolution: "resolved"` will never return the key.
2. Open `/activity` in the Developer Portal to copy the provider's `account_id` and your agent's email address.
3. Sign in to the provider's own dashboard (or trigger its account-reset flow) to rotate or reissue the credential.
4. If the provider has no self-serve dashboard recovery, contact the support or security address listed in its discovery document or guide.

## Revoking an agent does not rotate provider keys

Using the **Revoke agent** kill switch in `/dashboard` or `/agents/[id]` stops that agent from minting new tokens or reading its inbox in Agent Registrar. It does **not** reach into third-party providers to revoke existing API keys or delete accounts.

When retiring an agent or responding to a leak, revoke the agent in Agent Registrar **and** rotate or revoke each provider credential listed in `/activity` as a separate step.
