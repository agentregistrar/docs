Failures come from four layers: your MCP client's OAuth connection, browser consent gates, broker MCP tool calls, and the provider's signup endpoint. Broker tools return a structured error envelope with a stable `code`, a `retryable` boolean, and `side_effects` showing what did or did not happen. Branch on the error code rather than prose.

## OAuth and MCP connection errors

An unauthenticated request to `https://agentregistrar.dev/mcp` is supposed to return `401` with a `WWW-Authenticate` header pointing to `/.well-known/oauth-protected-resource`. That challenge triggers OAuth discovery and is not a server outage.

```bash
curl -sS -D - -o /dev/null https://agentregistrar.dev/mcp
```

| Symptom | Likely cause | Fix |
| :--- | :--- | :--- |
| Config ignored or stdio error (Claude Code, VS Code) | Missing `"type": "http"`, or wrong top-level key (`servers` vs `mcpServers`) | Match the exact snippet in [Connect your tool](/agents/install/) and remove any trailing slash on `/mcp` |
| Transport error in Antigravity CLI | Used `httpUrl` or `url` instead of `serverUrl` | Change the config field to `"serverUrl": "https://agentregistrar.dev/mcp"` |
| Nothing happens in Claude Desktop | URL added to `claude_desktop_config.json` (stdio only) | Remove it and add a Custom Connector under **Customize > Connectors** |
| `401` after a working session | Bearer token expired, refresh failed, or session disconnected in `/agents/[id]` | Re-run OAuth login in your tool; reconnecting an existing active agent keeps its ID and inbox |
| `invalid_client` or registration fails | Stale DCR registration, or client tried CIMD and hit an issue | Remove and re-add the server so it re-registers (in Codex CLI, try `--oauth-client-registration dcr`) |
| Client asks for a pre-registered `clientId` | Client build does not support DCR or CIMD | Agent Registrar does not issue manual client IDs in the portal; use a client that supports DCR or CIMD |
| Browser does not open or callback fails | Headless/SSH session, firewall blocking loopback, or occupied callback port | Complete OAuth on a desktop session with a browser, free the callback port (or pass `--callback-port`), or paste the printed URL manually |
| Connected to the wrong human account | Browser was already signed in to another GitHub account | Log out in the client, sign out of GitHub in the browser, and reconnect |
| Connected, but zero tools listed | Initialization failed, wrong transport, or stale tool cache | Verify Streamable HTTP transport, remove any manual `Authorization` header, and refresh or clear the client's tool cache |

## Browser consent blocks (`/oauth/authorize`)

| Symptom or code | Cause | Fix |
| :--- | :--- | :--- |
| Redirected to `/onboarding/verify-email` or `email_verification_required` | Your human email is not verified yet | Enter the six-digit code sent to your email; you will return to the same OAuth consent screen automatically |
| Master Agreement prompt on consent screen | Current Master Agent Delegation Agreement (`v2026-10-01`) is unsigned | Review and check the inline acceptance box before clicking **Approve & Connect Harness** |
| Active agent limit reached (`agent_limit_reached`) | You already have `2 of 2` active agents (or reached your account quota) | Select **Connect to an existing active agent** on the consent screen, or revoke an unused agent in `/dashboard` first |
| Approval button disabled with operator suspension notice | An agent on your account is currently `suspended` by the broker operator | New OAuth connections are blocked until the suspension is reviewed and resolved; check **Abuse Reports** on the agent page or contact `security@agentregistrar.dev` |
| `403` "Master Agent Delegation ToS has not been signed" on `/mcp` | Master Agreement was not signed before tool calls ran | Sign the agreement in `/onboarding/tos` or re-run browser OAuth consent |

## `identity_signup` and `identity_record_signup` errors

| Code | Retryable | Cause | Fix |
| :--- | :--- | :--- | :--- |
| `rp_unverified` | no | Provider publishes no verification credential, and your `/trust` policy is `verify` or `strict` | Confirm you trust the provider, then add a per-provider `no_verify` override in `/trust` (or ask the provider to verify its domain) |
| `rp_broker_untrusted` | no | Provider's verification credential was issued by a broker not in your trust list | Review the broker under **Advanced: federated broker trust** in `/trust` before deciding whether to trust it |
| `rp_attestation_mode_not_allowed` | no | Your `/trust` policy is `strict` (broker-managed only), but the provider uses provider-managed verification | Switch policy to `verify` for that service in `/trust`, or do not proceed |
| `rp_blocked` | no | You added this provider to your blocklist in `/trust` | Remove the block entry in `/trust` only if you want to allow signups again |
| `rp_suspended` | no | Provider or its verification credential is suspended or revoked | Do not proceed; wait for the provider to resolve its status |
| `rp_attestation_invalid` / `rp_attestation_expired` | no | Provider's verification credential failed signature or expiry checks | Do not retry blindly; report the issue to the provider |
| `rp_broker_unavailable` | yes | Temporary outage reaching the attesting broker or its JWKS | Retry the same `identity_signup` or `identity_record_signup` call |
| `discovery_unreachable` | yes | Provider's `/.well-known/agent-signup.json` or `terms.url` timed out or returned `5xx` | Retry the same call; nothing was minted |
| `discovery_invalid` | no | Discovery document is missing (`404`), malformed, uses an unsupported protocol version, or `terms.url` is unreadable | Service does not conform to Agent Identity Protocol `v2.1.0`; stop and notify the provider |
| `scope_not_granted` | no | Provider requires a scope your agent does not hold, or `requested_scopes` was empty | Check `identity_whoami` for granted scopes; omit `requested_scopes` to use the provider's `required_scopes` |
| `discovery_source_not_allowed` | no | Passed forbidden fields (`rp_discovery`, `rp_discovery_url`, `rp_attestation`) to `identity_signup`, or passed `rp_attestation` without `signup_token` to `identity_record_signup` | Call `identity_signup` with `{ service }` only; pass `signup_token` with `identity_record_signup` |
| `ledger_email_failed` | yes | Terms acceptance was recorded, but sending the emailed copy failed | Retry the exact same `identity_signup` call; only the email delivery is retried |
| `signup_token_not_linked` | no | Receipt references an acceptance not recorded for this agent | Run `identity_signup` for that service first, then retry `identity_record_signup` |
| `signup_token_invalid` | no | Receipt signature, structure, or historical attestation window check failed | Obtain a valid provider-signed receipt (and exact `rp_attestation` if required); do not retry the rejected token |
| `signup_token_ownership_mismatch` | no | Receipt belongs to a different agent or human owner | Use the receipt issued for the active session's agent |
| `human_email_unverified` / `master_tos_unsigned` / `human_suspended` | no | Human account gate failed | Complete onboarding or contact `security@agentregistrar.dev` if suspended |

### Provider HTTP signup errors

When the agent POSTs `signup_request` to the provider, conformant services return stable error codes:

| Provider `error` | HTTP | Meaning | Action |
| :--- | :--- | :--- | :--- |
| `invalid_request` | `400` | Malformed header or body | Send `signup_request` verbatim (`Authorization: Bearer <jwt>`, body `{}`) |
| `invalid_assertion` / `assertion_expired` | `401` | Token signature failed or five-minute TTL passed | Call `identity_signup` again for a fresh token (reuses the same acceptance) |
| `issuer_not_allowed` | `403` | Provider does not allow `https://agentregistrar.dev` | Stop; the provider does not accept this broker |
| `audience_mismatch` | `403` | Token `aud` did not match provider's expected audience | Re-run `identity_signup` against the provider's canonical origin |
| `insufficient_scope` / `human_unverified` | `403` | Missing required scope or unverified human email | Confirm scopes in `identity_whoami` and email status in `/settings` |
| `assertion_replayed` | `409` | Token `jti` reused in a conflicting context | Mint a fresh token via `identity_signup` |
| `tos_hash_mismatch` | `409` | Provider updated its terms since acceptance | Re-run `identity_signup` to fetch and accept the updated terms |
| `rate_limited` | `429` | Provider throttled the request | Back off and retry after the advertised delay |

Remember: `resolution: "resolved"` with no API key is a **success**, not an error. See [Credentials and recovery](/agents/credentials-and-recovery/) if you lost a show-once key.

## `inbox_read` errors and timeouts

| Symptom or code | Cause | Fix |
| :--- | :--- | :--- |
| `wait_timeout` (`retryable: true`) | No matching inbound email arrived within `wait_seconds` (max `25`) and `since_seconds_ago` (default `120`) | Call `inbox_read` with `{}` to list recent messages, or raise `since_seconds_ago` (up to `3600`) and retry |
| Email exists in portal, but `inbox_read` missed it | `from_contains` or `subject_contains` did not match the raw header | Match against the actual sender email address or a short subject keyword, or list without filters |
| `message_not_found` | UUID belongs to another agent or does not exist | Call `inbox_read` without `message_id` and copy an ID from the returned list |
| `detected_otp` is `null` | Email had no standalone six-digit number (for example an eight-digit code or a magic link) | Read `text_body` or `html_body` directly from the returned message |

## Revoked vs. suspended agents

Both states return `agent_revoked` on `identity_whoami`, `identity_signup`, and `inbox_read` (a suspension includes a suspension-specific message):

- **If you clicked Revoke agent (`revoked`):** open `/agents/[id]` and click **Reactivate agent** to resume the same identity and inbox, or connect a new agent via browser OAuth if you want a fresh identity.
- **If the broker operator suspended the agent (`suspended`):** the kill switch is hidden and cannot restore the agent, and new OAuth connections are paused. Open the **Abuse Reports** tab on `/agents/[id]` to review the case, resolve any issue with the reporting provider, and appeal to `security@agentregistrar.dev` with the agent ID and case ID.

## Where to report bugs or security issues

- **Security issues and suspension appeals:** `security@agentregistrar.dev` (never include live API keys, JWTs, or passwords).
- **Protocol or documentation issues:** [agentregistrar/spec issues](https://github.com/agentregistrar/spec/issues).
- **Provider-specific errors:** the `contact` address listed in that provider's discovery document.
