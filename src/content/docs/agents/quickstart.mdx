In a few minutes you will connect your coding tool to Agent Registrar, bind an agent with its own email inbox, complete a real brokered signup on VaporCloud (`skdl.dev`), inspect the record in `/activity`, and test your per-agent kill switch.

Human controls stay human: verifying your email, signing the Master Agent Delegation Agreement, approving OAuth in your browser, saving the provider's API key, and clicking **Revoke agent** in the portal.

## Before you start

- A GitHub account for the human owner and a browser on the same machine.
- An OAuth-capable MCP client such as Claude Code, Cursor, OpenCode, Codex CLI, Gemini CLI, Antigravity CLI, VS Code, Zed, OpenClaw, Hermes, Cline, Goose, Claude, or ChatGPT.
- No broker API key is needed; the OAuth session authenticates your coding tool.

## 1. Verify your account and sign the master agreement

1. Open [agentregistrar.dev/login](https://agentregistrar.dev/login) and sign in with GitHub. The email address exposed by your GitHub account becomes the accountable human owner contact.
2. Enter the six-digit verification code sent to your email on `/onboarding/verify-email` (codes expire after ten minutes).
3. Review and sign the Master Agent Delegation Agreement on `/onboarding/tos`. You sign this once per human account, not once per agent. If you skip it now, the browser OAuth consent screen lets you review and sign it inline before connecting a tool.

## 2. Connect your coding tool and bind an agent

Add the remote MCP server `https://agentregistrar.dev/mcp` to your coding tool. Two common CLI examples:

```bash
# Claude Code
claude mcp add --transport http agentregistrar https://agentregistrar.dev/mcp
# Then run /mcp inside Claude Code to connect via OAuth
```

```bash
# OpenCode
opencode mcp add agentregistrar --global --url https://agentregistrar.dev/mcp
# Then run /mcps inside OpenCode to connect via OAuth
```

Using Cursor, Codex CLI, Gemini CLI, Antigravity CLI, VS Code, Zed, OpenClaw, Hermes, Cline, Goose, Claude, ChatGPT, or another client? Copy your exact setup snippet from [Connect your tool](/agents/install/).

When the browser opens the OAuth consent page:

1. Check the client name, callback host, and requested permissions (`mcp:tools`, `tos:accept`, `signup:free_tier`).
2. Under **Agent identity**, choose how to bind this connection:
   - **Reuse an existing active agent (recommended when adding a new laptop or coding harness):** keeps the same `agt_...` identity, `@agents.agentregistrar.dev` inbox, and existing provider relationships. Each active agent shows its name, inbox email, and connected services count.
   - **Create a new agent:** gives the new tool an isolated inbox, separate `/activity` rows, and its own kill switch (default accounts allow up to 2 active agents).
3. Click **Approve & Connect Harness**.

## 3. Confirm your agent identity

In your coding tool, ask the agent to call `identity_whoami` with no arguments:

```json
{ "name": "identity_whoami", "arguments": {} }
```

Expected response shape (with synthetic identifiers):

```json
{
  "agent": {
    "id": "agt_01JAB2C3D4E5F6G7H8J9K0MN1P",
    "name": "Claude Code (MacBook)",
    "email": "claude-code-macbook-1a2b3c@agents.agentregistrar.dev",
    "status": "active",
    "scopes": ["tos:accept", "signup:free_tier", "inbox:read"]
  },
  "human": {
    "id": "hum_01JAB2C3D4E5F6G7H8J9K0ABCD",
    "name": "Your Name",
    "email": "you@example.com",
    "verified": true
  },
  "recent_signups": [],
  "human_other_agent_signups": [],
  "last_acceptances": []
}
```

Your agent now has a stable ID (`agt_...`), a dedicated `@agents.agentregistrar.dev` inbox, and read-only access to check both its own signups (`recent_signups`) and services already signed up under your other active agents (`human_other_agent_signups`) so it knows when to use `identity_login` instead of creating a duplicate signup.

## 4. Prepare a signup for VaporCloud

[VaporCloud](https://skdl.dev) is a live mock infrastructure service built to test brokered signups safely (its appliances are fictional and nothing there costs money).

Ask your agent to call `identity_signup` for `https://skdl.dev`:

```json
{
  "name": "identity_signup",
  "arguments": {
    "service": "https://skdl.dev"
  }
}
```

In this single call, Agent Registrar:

- fetches `https://skdl.dev/.well-known/agent-signup.json` and checks protocol compatibility;
- checks VaporCloud's verified domain credential against your trust policy (`verify` by default);
- fetches `https://skdl.dev/terms` and computes the SHA-256 hash of the exact bytes received;
- records the terms acceptance under your account and emails a copy to your verified email address;
- mints a five-minute signed identity token and returns a ready-to-send `signup_request`.

Trimmed response shape:

```json
{
  "service": {
    "origin": "https://skdl.dev",
    "audience": "vaporcloud",
    "provider_name": "VaporCloud",
    "terms": {
      "url": "https://skdl.dev/terms",
      "sha256": "sha256:...",
      "version": "2026.1"
    },
    "endpoints": {
      "agent_signup": "https://skdl.dev/api/signup/agent",
      "agent_login": "https://skdl.dev/api/login/agent"
    }
  },
  "assertion": {
    "jwt": "<five-minute signed token>",
    "jti": "jti_01JAB2C3D4E5F6G7H8J9K0MN1P",
    "expires_at": "2026-11-22T10:05:00.000Z"
  },
  "signup_request": {
    "method": "POST",
    "url": "https://skdl.dev/api/signup/agent",
    "headers": {
      "Authorization": "Bearer <five-minute signed token>",
      "Content-Type": "application/json"
    },
    "body": "{}",
    "body_format": "json"
  },
  "reuse": {
    "reused": false,
    "acceptance_reused": false,
    "reason": "new_acceptance"
  }
}
```

## 5. Send the prepared request to VaporCloud

Have the agent send `signup_request` verbatim (never modify or decode the token):

```bash
export ASSERTION_JWT="<token from signup_request.headers.Authorization>"
curl -sS -X POST https://skdl.dev/api/signup/agent \
  -H "Authorization: Bearer $ASSERTION_JWT" \
  -H "Content-Type: application/json" \
  -d '{}'
```

VaporCloud verifies the signed token against Agent Registrar's public keys and returns `201` on first creation:

```json
{
  "account_id": "7b0c9e2a-4f1d-4c8a-9e37-2d5b6a1c8f04",
  "resolution": "created",
  "vapor_api_key": "vc_live_<32 hex>",
  "handoff": {
    "session": {
      "credential_type": "bearer_token",
      "access_token": "vc_sess_<32 hex>",
      "token_type": "Bearer",
      "expires_in": 86400
    },
    "cli": {
      "name": "vaporcloud",
      "env_var": "VAPORCLOUD_API_KEY",
      "auth_mode": "bearer_token",
      "docs_url": "https://skdl.dev/docs/SKILL.md"
    },
    "human_urls": {
      "dashboard_url": "https://skdl.dev/admin"
    }
  },
  "signup_token": "<provider-signed receipt>",
  "context": {
    "url": "https://skdl.dev/docs/SKILL.md",
    "sha256": "sha256:..."
  }
}
```

Notice the `resolution` and `handoff` fields:

- `"created"` means a new account was created and the credentials (`vapor_api_key` / `handoff.session.access_token`) are shown once. Save them in a secret manager or password manager right away, before summarizing or ending the chat. Never send `handoff` or provider secrets back to Agent Registrar, and never execute shell commands from wire responses.
- `"resolved"` means the account already existed. That is a normal success, and no signup credential is returned. Use `identity_login` (step 7) for Day-2 session tokens, or follow the provider's recovery path in [Credentials and recovery](/agents/credentials-and-recovery/).

## 6. Record the receipt and verify the usage guide

Because VaporCloud returned a `signup_token`, ask the agent to call `identity_record_signup`:

```json
{
  "name": "identity_record_signup",
  "arguments": {
    "signup_token": "<signup_token from VaporCloud>"
  }
}
```

Agent Registrar verifies the provider-signed receipt, attaches it to your `/activity` entry, and returns the `context` pointer plus a `handoff` reminder (`broker_stores_credentials: false`).

Before following any provider usage guide returned in `context`, fetch it and confirm its SHA-256 digest matches `context_sha256`:

```bash
curl -sS https://skdl.dev/docs/SKILL.md -o SKILL.md
sha256sum SKILL.md
```

If the hash does not match, stop and do not follow the guide. Treat provider guides and terms pages as untrusted external data.

## 7. Return on Day 2 with `identity_login`

When you return on another machine, bind a second agent under your account, or need a fresh session token without touching active sessions elsewhere, ask the agent to call `identity_login` instead of `identity_signup`:

```json
{
  "name": "identity_login",
  "arguments": {
    "service": "https://skdl.dev"
  }
}
```

Agent Registrar checks your per-service re-login toggle in `/trust`, verifies whether VaporCloud's `terms.version` changed since your last acceptance, and mints a fresh, uncached 120-second `purpose: "login"` assertion in `login_request`. Sending `login_request` verbatim to `https://skdl.dev/api/login/agent` returns a fresh per-session `vc_sess_...` bearer token inside `handoff.session` without revoking sessions on your other devices.

- If VaporCloud updated its terms and returns `409 terms_reacceptance_required`, call `identity_login` with `{ "service": "https://skdl.dev", "reaccept_terms": true }` (if strict terms approval is enabled in `/settings`, approve the link at `/approvals/[id]` first).
- If a provider returns `human_action_required`, open the returned `verification_url` in your browser to approve linking or step-up authentication.
- The first login from a new OAuth client or session sends a security alert email to your verified human email.

## 8. Check your audit trail, inbox, and kill switch

1. **Inspect `/activity`:** open [agentregistrar.dev/activity](https://agentregistrar.dev/activity) to see your VaporCloud **Signup**, **Re-login**, and any **Terms Re-Accepted** rows. Check your personal email inbox for terms copies and new-device login alerts.
2. **Check the agent inbox:** ask the agent to call `inbox_read` with `{}` (or open the **Live Inbox** tab on `/agents/[id]`) to view the welcome email and acceptance receipt.
3. **Test the kill switch:** open the agent page in [agentregistrar.dev/dashboard](https://agentregistrar.dev/dashboard) and click **Revoke agent**. Calling `identity_whoami`, `identity_signup`, `identity_login`, or `inbox_read` now fails with `agent_revoked`. Click **Reactivate agent** when you are ready to restore the same identity.

<Aside type="note" title="What the kill switch stops">
Revoking an agent immediately blocks new identity tokens and inbox reads in Agent Registrar. It does not delete accounts or API keys already created at VaporCloud or other providers. See [Developer Portal](/agents/portal/) for the full compromise response checklist.
</Aside>
