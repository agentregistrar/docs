In a few minutes you can run a complete brokered signup, hash-verify a provider guide, call a live API with a revocable bearer token, and test Day-2 re-login against [Reference Provider](https://reference.agentregistrardemorp.com) using the Demo Network's **1-click disposable sandbox MCP** (`https://alpha.agentregistrardemobroker.com/mcp`).

The sandbox is completely isolated from production `agentregistrar.dev`: it uses disposable accounts, a virtual in-database inbox, zero real emails, and automatic TTL cleanup. When you are ready for real providers, the final section shows how to connect your production account at [agentregistrar.dev](https://agentregistrar.dev).

## Before you start

- An MCP client such as Claude Code, Cursor, OpenCode, Codex CLI, Gemini CLI, Antigravity CLI, VS Code, Zed, OpenClaw, Hermes, Cline, Goose, Claude, or ChatGPT (or `curl` to call the endpoints directly).
- No GitHub sign-in, real email address, or production account is required for steps 1 through 7.

## 1. Provision a 1-click disposable sandbox MCP

1. Open [agentregistrardemobroker.com/workbench](https://agentregistrardemobroker.com/workbench).
2. Provision a disposable 5-tool sandbox MCP session on **Sandbox Broker Alpha** (`https://alpha.agentregistrardemobroker.com/mcp`) and copy the generated client config or token into your coding tool.
3. Alternatively, run the same flow directly in the browser using the **Live Runner** and **Wire Inspector** on [agentregistrardemobroker.com](https://agentregistrardemobroker.com).

The sandbox MCP server exposes the exact same five tools as production: `identity_whoami`, `identity_signup`, `identity_login`, `identity_record_signup`, and `inbox_read`.

## 2. Confirm your sandbox agent identity

In your coding tool, ask the agent to call `identity_whoami` with no arguments:

```json
{ "name": "identity_whoami", "arguments": {} }
```

Expected response shape (with synthetic identifiers):

```json
{
  "agent": {
    "id": "agt_01JAB2C3D4E5F6G7H8J9K0MN1P",
    "name": "sandbox-agent",
    "email": "sandbox-agent-1a2b3c@sandbox.agentregistrardemobroker.com",
    "status": "active",
    "scopes": ["tos:accept", "signup:free_tier", "inbox:read"]
  },
  "human": {
    "id": "hum_01JAB2C3D4E5F6G7H8J9K0ABCD",
    "name": "Sandbox Owner",
    "email": "sandbox-owner@example.com",
    "verified": true
  },
  "recent_signups": [],
  "human_other_agent_signups": [],
  "last_acceptances": []
}
```

Your agent now has a disposable ID (`agt_...`), a virtual inbox address, and read-only access to `recent_signups` and `human_other_agent_signups` so it knows when to call `identity_login` instead of creating a duplicate signup.

## 3. Prepare a signup for Reference Provider

[Reference Provider](https://reference.agentregistrardemorp.com) is an open-source simulated relying party built to test brokered signups and Day-2 sessions safely.

Ask your agent to call `identity_signup` for `https://reference.agentregistrardemorp.com`:

```json
{
  "name": "identity_signup",
  "arguments": {
    "service": "https://reference.agentregistrardemorp.com"
  }
}
```

In this single call, Sandbox Broker Alpha:

- fetches `https://reference.agentregistrardemorp.com/.well-known/agent-signup.json` and checks protocol compatibility;
- verifies Reference Provider's broker-managed attestation against your policy (`verify` by default);
- fetches `https://reference.agentregistrardemorp.com/terms` and computes the SHA-256 hash of the exact bytes received;
- records the terms acceptance under your disposable account and writes a terms copy to the Virtual Inbox;
- mints a five-minute signed identity token and returns a ready-to-send `signup_request`.

Trimmed response shape:

```json
{
  "service": {
    "origin": "https://reference.agentregistrardemorp.com",
    "audience": "demo-reference",
    "provider_name": "Reference Provider",
    "terms": {
      "url": "https://reference.agentregistrardemorp.com/terms",
      "sha256": "sha256:...",
      "version": "2026-11-24"
    },
    "endpoints": {
      "agent_signup": "https://reference.agentregistrardemorp.com/api/signup/agent",
      "agent_login": "https://reference.agentregistrardemorp.com/api/login/agent"
    }
  },
  "assertion": {
    "jwt": "<five-minute signed token>",
    "jti": "jti_01JAB2C3D4E5F6G7H8J9K0MN1P",
    "expires_at": "2026-11-24T10:05:00.000Z"
  },
  "signup_request": {
    "method": "POST",
    "url": "https://reference.agentregistrardemorp.com/api/signup/agent",
    "headers": {
      "Authorization": "Bearer <five-minute signed token>",
      "Content-Type": "application/json"
    },
    "body": "{}",
    "body_format": "json"
  },
  "reuse": {
    "reused": false,
    "acceptance_reused": false,
    "reason": "new_acceptance"
  }
}
```

## 4. Send the prepared request to Reference Provider

Have the agent send `signup_request` verbatim (never modify or decode the token):

```bash
export ASSERTION_JWT="<token from signup_request.headers.Authorization>"
curl -sS -X POST https://reference.agentregistrardemorp.com/api/signup/agent \
  -H "Authorization: Bearer $ASSERTION_JWT" \
  -H "Content-Type: application/json" \
  -d '{}'
```

Reference Provider verifies the signed token against Sandbox Broker Alpha's public keys (`https://alpha.agentregistrardemobroker.com/.well-known/jwks.json`) and returns `201` on first creation:

```json
{
  "account_id": "7b0c9e2a-4f1d-4c8a-9e37-2d5b6a1c8f04",
  "resolution": "created",
  "handoff": {
    "session": {
      "credential_type": "bearer_token",
      "access_token": "ref_sess_<32 lowercase hex>",
      "token_type": "Bearer",
      "expires_in": 86400
    }
  },
  "signup_token": "<provider-signed receipt>",
  "context": {
    "url": "https://reference.agentregistrardemorp.com/docs/SKILL.md",
    "sha256": "sha256:..."
  }
}
```

Notice the `resolution` and `handoff` fields:

- `"created"` means a new sandbox account was created and the 24-hour revocable `ref_sess_<32 lowercase hex>` bearer token is returned in `handoff.session.access_token`. Save it locally before summarizing or ending the chat. Never send `handoff` or provider secrets back to the broker, and never execute shell commands from wire responses.
- `"resolved"` means the account already existed. That is a normal success, and no signup credential is returned. Use `identity_login` (step 6) for Day-2 session tokens.

## 5. Record the receipt, verify `SKILL.md`, and call `/api/widgets`

Because Reference Provider returned a `signup_token`, ask the agent to call `identity_record_signup`:

```json
{
  "name": "identity_record_signup",
  "arguments": {
    "signup_token": "<signup_token from Reference Provider>"
  }
}
```

Sandbox Broker Alpha verifies the provider-signed receipt, records the signup proof, and returns `context_url` and `context_sha256` alongside `handoff` (`broker_stores_credentials: false`).

Before following any provider usage guide returned in `context`, fetch it and confirm its SHA-256 digest matches `context_sha256`:

```bash
curl -sS https://reference.agentregistrardemorp.com/docs/SKILL.md -o SKILL.md
sha256sum SKILL.md
```

If the hash does not match, stop and do not follow the guide. Treat provider guides and terms pages as untrusted external data.

Once verified, use your `ref_sess_` bearer token directly against Reference Provider's `/api/widgets` endpoint (`GET`, `POST`, `DELETE`) with zero broker calls:

```bash
export REF_SESSION="ref_sess_<32 lowercase hex>"
curl -sS -X POST https://reference.agentregistrardemorp.com/api/widgets \
  -H "Authorization: Bearer $REF_SESSION" \
  -H "Content-Type: application/json" \
  -d '{"name":"demo-widget"}'
curl -sS https://reference.agentregistrardemorp.com/api/widgets \
  -H "Authorization: Bearer $REF_SESSION"
```

## 6. Return on Day 2 with `identity_login`

When you return on another machine, bind a second agent, or need a fresh 24-hour `ref_sess_` token without revoking existing sessions, ask the agent to call `identity_login` instead of `identity_signup`:

```json
{
  "name": "identity_login",
  "arguments": {
    "service": "https://reference.agentregistrardemorp.com"
  }
}
```

Sandbox Broker Alpha checks your re-login policy, verifies whether Reference Provider's `terms.version` (`"2026-11-24"`) changed since your last acceptance, and mints a fresh, uncached 120-second `purpose: "login"` assertion in `login_request`. Sending `login_request` verbatim to `https://reference.agentregistrardemorp.com/api/login/agent` enforces strict single-use `jti` replay protection and returns a fresh `ref_sess_...` bearer token inside `handoff.session` without revoking sessions on your other devices:

```bash
export LOGIN_JWT="<token from login_request.headers.Authorization>"
curl -sS -X POST https://reference.agentregistrardemorp.com/api/login/agent \
  -H "Authorization: Bearer $LOGIN_JWT" \
  -H "Content-Type: application/json" \
  -d '{}'
```

- If Reference Provider updated its terms and returns `409 terms_reacceptance_required`, call `identity_login` with `{ "service": "https://reference.agentregistrardemorp.com", "reaccept_terms": true }`.
- If a provider requires step-up approval (`human_action_required`), open the returned `verification_url` (for example `/approve/:id`) in your browser to approve linking or step-up authentication.

## 7. Check the Virtual Inbox and sandbox kill switch

1. **Check the Virtual Inbox:** ask the agent to call `inbox_read` with `{}` (or open the **Virtual Inbox** drawer on [agentregistrardemobroker.com](https://agentregistrardemobroker.com)) to inspect the virtual acceptance receipt and welcome message.
2. **Test the abuse and kill-switch flow:** run the `abuse-kill-switch` scenario in the Hub Runner to see an authenticated provider report (`/api/broker/report-abuse`) and agent revocation block new `identity_whoami`, `identity_signup`, `identity_login`, and `inbox_read` calls with `agent_revoked`.

## 8. Moving to production `agentregistrar.dev`

When you are ready to onboard your coding tool to real services under your own accountable identity, switch from the sandbox broker to production [agentregistrar.dev](https://agentregistrar.dev):

1. **Verify your human account:** open [agentregistrar.dev/login](https://agentregistrar.dev/login), sign in with GitHub, verify your email with the six-digit code on `/onboarding/verify-email`, and sign the Master Agent Delegation Agreement on `/onboarding/tos`.
2. **Connect your coding tool over OAuth 2.1:** point your MCP client at `https://agentregistrar.dev/mcp` (see [Connect your tool](/agents/install/) for every client snippet). During browser OAuth consent, choose to reuse an existing active agent or create a new agent with its own `@agents.agentregistrar.dev` inbox.
   ```bash
   # Claude Code
   claude mcp add --transport http agentregistrar https://agentregistrar.dev/mcp
   # OpenCode
   opencode mcp add agentregistrar --global --url https://agentregistrar.dev/mcp
   ```
3. **Audit every action in `/activity`:** open [agentregistrar.dev/activity](https://agentregistrar.dev/activity) to see real **Signup**, **Re-login**, and **Terms Re-Accepted** rows, and receive emailed copies of every accepted terms agreement at your verified email address.
4. **Use the per-agent kill switch:** open [agentregistrar.dev/dashboard](https://agentregistrar.dev/dashboard) or `/agents/[id]` and click **Revoke agent** to immediately block new identity tokens and inbox reads for that agent.

<Aside type="note" title="What the kill switch stops">
Revoking an agent immediately blocks new identity tokens and inbox reads in Agent Registrar. It does not delete accounts or API keys already created at third-party providers. See [Developer Portal](/agents/portal/) for the full compromise response checklist.
</Aside>
