The Demo Network is a deployed 7-host open-source testbed for the Agent Identity Protocol (`v2.3.0`, wire `protocol_version: "2.0"`), published at [agentregistrar/demo-network](https://github.com/agentregistrar/demo-network) (Apache-2.0, Hono + SQLite/D1). It pairs two sandbox brokers with three simulated relying parties, a live runner, and a Provider Workbench so you can test same-broker, cross-broker, unverified-policy, Day-2 lifecycle, and abuse kill-switch flows without touching production accounts.

All seven hosts are **completely isolated** from production `agentregistrar.dev` and are **simulated third parties** operated as a public sandbox. They use disposable accounts, a virtual in-database inbox, zero real emails, and automatic TTL cleanup. They carry no provisioning, billing, SLA, uptime, or endorsement claims.

<Aside type="note" title="Strict sandbox isolation">
Nothing you run on the Demo Network writes to your real `agentregistrar.dev` account or sends real email. To test against production accounts and real providers, connect `https://agentregistrar.dev/mcp` in the [Agent quickstart](/agents/quickstart/).
</Aside>

## Seven live hosts

| Host | Role | Registered with | Attestation | What it provides |
| :--- | :--- | :--- | :--- | :--- |
| [Hub & Workbench](https://agentregistrardemobroker.com) | Hub UI (indexed) | n/a | n/a | Live 7-host status, 5-scenario Live Runner, Wire Inspector, Virtual Inbox drawer, and `/workbench` |
| [Sandbox Broker Alpha](https://alpha.agentregistrardemobroker.com/.well-known/agent-broker.json) | Human/agent sandbox broker (`noindex`) | Home sandbox broker | Issues broker-managed attestations | Contract A assertions, disposable 5-tool `/mcp`, JWKS, status, receipts, and abuse endpoint |
| [Sandbox Broker Beta](https://beta.agentregistrardemobroker.com/.well-known/agent-broker.json) | Provider sandbox broker (`noindex`) | RP-only broker | Issues Contract G attestations | Independent broker issuing provider-managed attestations for cross-broker federation |
| [Demo RP Directory](https://agentregistrardemorp.com) | RP landing (`noindex`) | None | None | Live directory and status probes for the simulated relying parties |
| [Reference Provider](https://reference.agentregistrardemorp.com/.well-known/agent-signup.json) | Reference RP (`noindex`) | Alpha | Alpha, `mode: "broker"` | `audience: "demo-reference"`; Day-2 `/api/login/agent`, `ref_sess_` tokens, `/api/widgets`, `/docs/SKILL.md` |
| [Federated Provider](https://federated.agentregistrardemorp.com/.well-known/agent-signup.json) | Federated RP (`noindex`) | Beta | Beta issues; RP hosts `mode: "provider"` | `audience: "demo-federated"`; `issuer_allowlist` trusts Alpha; cross-broker receipt to Alpha |
| [Unverified Provider](https://unverified.agentregistrardemorp.com/.well-known/agent-signup.json) | Minimal RP (`noindex`) | Neither | None | `audience: "demo-unverified"`; omits `attestation` to test `verify`, `strict`, `no_verify`, and `blocked` |

A verified provider publishes an optional `attestation` source object in discovery, never the token itself. **Reference Provider** uses broker-managed mode via Sandbox Broker Alpha, and **Federated Provider** uses provider-managed mode where Sandbox Broker Beta signs the Contract G attestation and Federated Provider hosts it at `https://federated.agentregistrardemorp.com/.well-known/agent-rp-attestation.json`. **Unverified Provider** omits `attestation`.

All three simulated providers share the registrable domain `agentregistrardemorp.com`. Their origins and audiences are separate, though they are not isolated from each other at the DNS boundary.

### Topology

<DemoNetworkDiagram variant="topology" />

Your disposable sandbox agent runs on Sandbox Broker Alpha. Reference Provider is registered with Alpha, Federated Provider is registered with Beta, and Unverified Provider is registered with neither. All three providers list `https://alpha.agentregistrardemobroker.com` in `issuer_allowlist`. Alpha and Beta share no account database.

### Cross-broker sequence

<DemoNetworkDiagram variant="sequence" />

Alpha serves the sandbox agent and verifies Beta's Contract G attestation against Beta's metadata and JWKS. Beta never mints a Contract A assertion in this flow. Federated Provider verifies Alpha's assertion against Alpha's JWKS, signs a receipt with its Beta-attested key, and posts the receipt plus the exact Beta attestation to Alpha (or returns `signup_token` for `identity_record_signup`). Alpha verifies the Beta attestation and key, then records the receipt.

## Hub Runner and Provider Workbench

The [Demo Network Hub](https://agentregistrardemobroker.com) lets you run and inspect protocol flows in your browser or point your own MCP client at a disposable sandbox server.

### Five Live Runner scenarios

Open [agentregistrardemobroker.com](https://agentregistrardemobroker.com) to step through all five scenarios with the built-in **Wire Inspector** (raw discovery JSON, JWT headers/claims, HTTP requests/responses) and **Virtual Inbox** drawer:

1. **`same-broker`**: Sandbox Broker Alpha mints a Contract A assertion for **Reference Provider** (`demo-reference`), verifies Alpha's broker-managed attestation, creates an account with a `ref_sess_` token, calls `/api/widgets`, and records the receipt.
2. **`cross-broker`**: Alpha verifies **Federated Provider** (`demo-federated`) using Sandbox Broker Beta's provider-managed Contract G attestation, mints an assertion, and ingests the Beta-attested cross-broker receipt.
3. **`unverified-policy`**: Alpha evaluates **Unverified Provider** (`demo-unverified`) across `verify`, `strict`, `no_verify`, and `blocked` policies.
4. **`day2-lifecycle`**: Exercises Day-2 `POST /api/login/agent` on Reference Provider with strict `jti` replay protection, `terms_reacceptance_required`, and step-up approval at `/approve/:id`.
5. **`abuse-kill-switch`**: Exercises authenticated provider abuse reporting (`/api/broker/report-abuse`) and agent revocation / kill-switch enforcement on Sandbox Broker Alpha.

### Provider Workbench (`/workbench`)

Open [agentregistrardemobroker.com/workbench](https://agentregistrardemobroker.com/workbench) to test your own service or connect an external MCP client:

- **Discovery validator:** inspect any `/.well-known/agent-signup.json` URL against protocol rules.
- **Contract A assertion generator:** generate positive or negative assertions with copyable `curl` commands and a live probe against your endpoint.
- **24-hour ephemeral provider onboarding:** register a temporary test origin/audience on the sandbox for end-to-end testing with automatic TTL cleanup.
- **1-click disposable 5-tool sandbox `/mcp`:** provision a short-lived MCP session on `https://alpha.agentregistrardemobroker.com/mcp` exposing all five tools (`identity_whoami`, `identity_signup`, `identity_login`, `identity_record_signup`, `inbox_read`) against the Virtual Inbox.

### Policy outcomes for an unverified or federated provider

| Policy | Reference RP result | Federated RP result | Unverified RP result |
| :--- | :--- | :--- | :--- |
| `no_verify` | Proceeds, verified | Proceeds, verified (when Beta trusted) | Proceeds, shown as unverified |
| `verify` (default) | Proceeds | Proceeds when Beta trusted; else `rp_broker_untrusted` | Blocked with `rp_unverified` |
| `strict` | Proceeds (`mode: "broker"`) | Blocked with `rp_attestation_mode_not_allowed` | Blocked with `rp_unverified` |
| `blocked` | Blocked with `rp_blocked` | Blocked with `rp_blocked` | Blocked with `rp_blocked` |

<Aside type="note" title="Trust is local policy">
Trusting Sandbox Broker Beta does not make every Beta statement authoritative, and it does not make a provider safe. `verified` means the credential verified under policy, not that the service is trustworthy.
</Aside>

## Inspect Reference Provider

[Reference Provider](https://reference.agentregistrardemorp.com) (`audience: "demo-reference"`) shows the exact boundary between the identity-only protocol and vendor-specific APIs. It implements `v2.3.0` with Alpha broker-managed verification (`issuer_allowlist: ["https://alpha.agentregistrardemobroker.com"]`), Day-2 `agent_login` with revocable 24-hour `ref_sess_` bearer tokens (`ref_sess_<32 lowercase hex>`), strict `jti` replay protection, `terms_reacceptance_required`, step-up `/approve/:id`, signed receipts, a hash-pinned post-signup guide, and authenticated abuse reporting (`security@agentregistrardemorp.com`).

| Path | Purpose |
| :--- | :--- |
| [`/.well-known/agent-signup.json`](https://reference.agentregistrardemorp.com/.well-known/agent-signup.json) | Identity-only discovery document (`audience: "demo-reference"`, `mode: "broker"`, `agent_signup` + `agent_login`) |
| [`/api/signup/agent`](https://reference.agentregistrardemorp.com/api/signup/agent) | Brokered signup endpoint (`POST` with `Authorization: Bearer <jwt>`) |
| [`/api/login/agent`](https://reference.agentregistrardemorp.com/api/login/agent) | Day-2 re-login endpoint (`POST` with `purpose: "login"` JWT, single-use `jti`, fresh `ref_sess_` session) |
| [`/terms`](https://reference.agentregistrardemorp.com/terms) | Provider-hosted terms (`version: "2026-11-24"`) fetched and SHA-256 hashed by the broker |
| [`/docs/SKILL.md`](https://reference.agentregistrardemorp.com/docs/SKILL.md) | Hash-pinned vendor API guide (`context.url` / `context.sha256`) documenting `/api/widgets` |
| `/api/widgets` | Vendor API (`GET`/`POST`/`DELETE`) authenticated with `Authorization: Bearer ref_sess_...` and zero broker calls |

Notice what Reference Provider keeps out of discovery: widget CRUD endpoints (`/api/widgets`) and session usage examples live in `/docs/SKILL.md`, fetched and SHA-256 verified only after signup.

## Validate discovery from the CLI

You do not need an account, SDK, or shared secret to validate the public discovery documents (all served with `Cache-Control: no-store`):

- [Reference Provider discovery](https://reference.agentregistrardemorp.com/.well-known/agent-signup.json)
- [Federated Provider discovery](https://federated.agentregistrardemorp.com/.well-known/agent-signup.json)
- [Unverified Provider discovery](https://unverified.agentregistrardemorp.com/.well-known/agent-signup.json)

Run the published [`@agentregistrar/discovery` validator](/protocol/validator/) directly with `npx`:

```bash
# Reference Provider: Alpha attestation, broker-managed
npx @agentregistrar/discovery@2.3.0 validate \
  https://reference.agentregistrardemorp.com/.well-known/agent-signup.json \
  --json --probe-jwks --verify-attestation --require-attestation \
  --trusted-rp-broker https://alpha.agentregistrardemobroker.com

# Federated Provider: Beta attestation, provider-managed
npx @agentregistrar/discovery@2.3.0 validate \
  https://federated.agentregistrardemorp.com/.well-known/agent-signup.json \
  --json --probe-jwks --verify-attestation --require-attestation \
  --trusted-rp-broker https://beta.agentregistrardemobroker.com

# Unverified Provider: conformant, unverified
npx @agentregistrar/discovery@2.3.0 validate \
  https://unverified.agentregistrardemorp.com/.well-known/agent-signup.json \
  --json --probe-jwks
```

Reference Provider and Federated Provider exit `0` with `valid: true` and a verified attestation (`mode: "broker"` for Reference, `mode: "provider"` for Federated). Unverified Provider exits `0` with `valid: true` and an unverified status. The validator reports conformance and attestation verification separately.

## Sandbox broker endpoints

Both Sandbox Broker Alpha and Sandbox Broker Beta expose standard broker metadata, public Ed25519 JWKS, attestation status, and abuse reporting endpoints:

```bash
curl -sS https://alpha.agentregistrardemobroker.com/.well-known/agent-broker.json
curl -sS https://alpha.agentregistrardemobroker.com/.well-known/jwks.json
curl -sS https://beta.agentregistrardemobroker.com/.well-known/agent-broker.json
curl -sS https://beta.agentregistrardemobroker.com/.well-known/jwks.json
```

Sandbox Broker Alpha also exposes `/api/broker/attestation-status`, `/api/broker/signup-receipt`, and `/api/broker/report-abuse`. To read a signed status JWT for Federated Provider's current Beta attestation, extract `jti` from its `attestation.uri` and query Sandbox Broker Beta:

```bash
URI="$(curl -sS https://federated.agentregistrardemorp.com/.well-known/agent-signup.json \
  | node -e 'let s="";process.stdin.on("data",d=>s+=d).on("end",()=>console.log(JSON.parse(s).attestation.uri))')"
JTI="$(curl -sS "$URI" \
  | node -e 'let s="";process.stdin.on("data",d=>s+=d).on("end",()=>{const p=JSON.parse(s).attestation.split(".")[1];console.log(JSON.parse(Buffer.from(p,"base64url")).jti)})')"
curl -sS "https://beta.agentregistrardemobroker.com/api/broker/attestation-status?jti=${JTI}"
```

The response is `{attestation_jti, status_jwt}`. The status JWT names the attestation in `sub`, reports `active`, `suspended`, or `revoked`, and expires in at most five minutes.

### Synthetic receipt shape

A signup receipt is a compact JWS signed by the provider's key. The decoded claims below are illustrative only and use synthetic values:

```json
{
  "iss": "https://reference.agentregistrardemorp.com",
  "sub": "agt_demo_example",
  "aud": "https://alpha.agentregistrardemobroker.com",
  "jti": "srp_demo_example",
  "iat": 1795564800,
  "assertion_jti": "jti_demo_example",
  "service": {
    "audience": "demo-reference",
    "origin": "https://reference.agentregistrardemorp.com",
    "provider_name": "Reference Provider",
    "provider_url": "https://reference.agentregistrardemorp.com",
    "account_id": "acct_demo_example",
    "attestation_jti": "rpa_demo_example",
    "key_id": "rp_example_1"
  },
  "agent": {
    "id": "agt_demo_example",
    "name": "sandbox-agent",
    "email": "sandbox-agent@sandbox.agentregistrardemobroker.com"
  },
  "human": {
    "id": "hum_demo_example",
    "name": "Sandbox Owner",
    "email": "owner@example.com",
    "verified": true
  },
  "tos": {
    "version": "2026-11-24",
    "url": "https://reference.agentregistrardemorp.com/terms",
    "sha256": "sha256:<64 hex characters>"
  },
  "context": {
    "url": "https://reference.agentregistrardemorp.com/docs/SKILL.md",
    "sha256": "sha256:<64 hex characters>"
  },
  "signed_up_at": "2026-11-24T00:00:00Z"
}
```

`context` is optional; when present it points to the provider's guide and is hash-pinned (the agent fetches and checks it, never the broker). A receipt carries no expiry and remains verifiable against the historical attestation snapshot it names. The provider can post `{signup_token, rp_attestation}` directly to `https://alpha.agentregistrardemobroker.com/api/broker/signup-receipt` (`rp_callback`), or the agent can submit it via `identity_record_signup` (`rp_signed`). Both carry the same cryptographic proof. Do not post the synthetic example; unsigned or mismatched receipts are rejected.

## Self-host the demo network

The entire 7-host stack is open source under Apache-2.0 (`Hono` + `SQLite/D1`). Run it locally to inspect the wire handlers or test a local relying party:

```bash
git clone https://github.com/agentregistrar/demo-network
cd demo-network
pnpm install
pnpm dev
```

## What you can and cannot test

| You can test | You cannot test |
| :--- | :--- |
| Live 5-scenario runner, Wire Inspector, Virtual Inbox, and `/workbench` assertion generator | Production GitHub OAuth accounts or real outbound email delivery |
| Disposable 5-tool sandbox `/mcp` on Sandbox Broker Alpha against Reference, Federated, Unverified, or a 24h ephemeral RP | DNS/browser isolation across Reference, Federated, and Unverified (they share `agentregistrardemorp.com`) |
| Same-broker signup (`Reference Provider`), cross-broker federation (`Federated Provider` + Beta), and policy gates (`Unverified Provider`) | Multi-broker governance or third-party production SLAs |
| Day-2 `/api/login/agent`, `ref_sess_` tokens, `/api/widgets`, `jti` replay protection, and `/api/broker/report-abuse` | Persistent long-term accounts (sandbox rows expire via automatic TTL cleanup) |
| Assertion verification with public JWKS, no account or SDK | Catalogs, billing, or infrastructure resale |
