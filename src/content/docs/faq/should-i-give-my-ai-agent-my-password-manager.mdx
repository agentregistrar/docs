Do not give an AI agent your personal password manager or browser session cookies, because both grant broad, unlogged access to every account you own. Agent Registrar isolates agent access by issuing each agent a separate sub-identity, a dedicated `@agents.agentregistrar.dev` email inbox, short-lived signed identity tokens, and a per-agent kill switch.

## How it works

With Agent Identity Protocol `v2.3.0`, you verify your email once and sign one Master Agent Delegation Agreement. When you connect a coding tool to the five-tool remote MCP server (`identity_whoami`, `identity_signup`, `identity_login`, `identity_record_signup`, `inbox_read`), it receives an OAuth 2.1 token bound to a single `agt_...` sub-identity rather than your personal login sessions.

Instead of reading your saved passwords, the agent requests a short-lived signed assertion (5 minutes for signup, 120 seconds for Day-2 login) and receives separate provider credentials directly in the `handoff` response. Every terms acceptance is SHA-256 hash-pinned, emailed to you, and visible in `/activity`. You can test this isolation against simulated providers on the [Demo Network](https://agentregistrardemobroker.com).

## Limits

Agent Registrar works only with providers that support `/.well-known/agent-signup.json`; legacy sites without brokered signup still require human-managed access. Revoking an agent stops new broker tokens and inbox reads, but does not delete existing third-party accounts. See [Trust and limits](/start/trust-and-limits/).
